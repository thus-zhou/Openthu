# Openthu 完整开发交接

交接基准：2026-11-16，首个公共版本 0.1.0。本文与代码、能力矩阵、Release 检查共同组成交付；任何历史测试结论都不替代当前运行结果。

## 目标与结构

Openthu 用统一工具入口访问校园服务，保留网络学堂兼容接口，并把查询、准备、授权执行和结果核对分开。

| 路径 | 责任与修改入口 |

| `scheduler.js`、`session-store.js`、`cookies.js`、`session-policy.js` | 串行调度、锁、账号绑定会话、Cookie 与认证证据 |

## 运行链

MCP 客户端 → Python 分派/业务适配 → Node 网关 → 固定认证依赖或校园站点。浏览器为独立实例。真实登录状态使用当前 Windows 用户的 DPAPI 保存，不发送到云端开发机。

每个 MCP 进程拥有一个网关；任务串行排队，认证锁和状态锁不覆盖整个网络请求。取消、断线或进程崩溃后不重放已发出的请求。发现不确定的事务时先核对已有记录。

## 必须保留的接口语义

- `status/source/checked_at/complete/warnings/verification_level` 一起解释。空数组或 HTTP 200 不自动证明业务成功。
- `snapshot_complete` 只代表快照读完；缺页、重复页、认证未知仍保留 PARTIAL/UNKNOWN。
- 游标绑定参数和进程内快照，十分钟有效；过期后重新查询，不拼接不同快照。
- 准备操作不等于提交。提交一次后核对本人记录和精确字段；审批、付款、未知结果分别保留状态。
- `authorization` 文本不是宿主授权证据，不能伪造或绕过执行框架。
- 模型只在未开始响应且明确 401 时刷新重试一次；额度不足、403、网络异常或已输出不自动重放。
- 真实凭据不得改用明文作为云端兼容方案。云端使用合成测试依赖。

## 当前已知问题与限制

1. 真实认证和事务存储依赖 Windows；Linux 支持开发、离线测试和静态目录，尚无生产级 Linux 凭据实现。
2. 图书馆与体育创建/取消已实现准备和核对框架，真实写入尚未按具体事项完成验收。
   图书馆续借只有资格读取、单笔计划、官方页面移交与新到期核对；没有已验证的请求端点，
   `renew_loan` 契约未启用，生产不派发续借。
3. 亲友来访专用读取/办理适配尚未实现；通用浏览器看到表单不代表业务已接通。
4. 作业提交仍只有本地准备与校验，没有真正交作业的能力。
5. 学校接口会变化。历史真实读取通过仅说明当时的版本和账号，公开版不携带那些业务记录。
6. 首个公共发行将分散依赖改为仓库布局；现有用户安装不由此自动升级。后续改动需做兼容检查。

## 接手后的首轮工作

先运行离线检查，再选一个 Issue 建立任务分支。优先改善安装与故障诊断、维护跨平台测试、补齐文档；新增校园适配先确认当前官方入口和只读契约。需要真实校园证据时提交清楚的本机验证请求，由本地维护者接手。不要从模拟数据推导新的站点规则。

Git 的提交与 PR 是代码事实来源；交接记录是开发现场来源。私有环境文件和聊天不属于项目依赖。
