# Hermes 与 Codex 人工接力

项目地址：https://github.com/thus-zhou/Openthu 。使用共享仓库、任务分支、Issue 和 PR；由使用者发起切换，不运行自动接力程序。

## 职责

Hermes 负责云端日常开发、离线测试和任务记录。Codex 负责疑难攻关、本机校园验证、集成审查、版本更新、Release 和项目维护管理。项目所有者决定需求与具体校园业务授权。任一方都可以提交改进，但同一任务同一时间只有一名负责者。

## Hermes 交出任务

1. 读取 AGENTS.md 和完整交接，建立 `hermes/<issue>-<slug>` 分支；在 Issue/PR 写明任务目标与验收标准。
2. 保存代码并提交。记录复现步骤、预期与实际、已尝试方法、失败日志摘要和需要 Codex 解决的问题；公开记录只保留合成或脱敏信息。
3. 复制 `handoffs/TEMPLATE.md` 为 `handoffs/<task-id>.md` 填写。运行 `python scripts/handoff.py <task-id> --to codex`，生成机器可读的代码提交检查点。
4. 提交交接文件并推送分支，创建或更新 PR。在 PR 标明“待 Codex 接手”，停止修改本任务。
5. 将 PR 链接交给使用者。使用者在 Codex 说：**请接手这个 PR：<链接>。**

## Codex 接手和交还

读取 PR、交接文档和检查点，拉取对应提交，检查工作区及远端新改动，再复现问题。开始前在 PR 明确接手；需要独立分支时使用 `codex/<issue>-<slug>` 并记录来源。解决后提交改动、运行必要测试，写明结果和剩余事项，生成 `--to hermes` 检查点并推送。使用者在 Hermes 说：**请继续这个 PR：<链接>，先读取最新交接。**

合并与正式发布由 Codex 按维护流程执行。接手并不意味着跳过独立检查或覆盖未合并工作。

## 公开协作与私有实测

Issue/PR 不放真实姓名、学号、手机号、证件、Cookie、密码、令牌、主机/IP、个人路径、截图或原始业务响应。无法公开的复现放在使用者受控的私有环境，由本地维护者核对；公共 PR 只写结论、合成样例和不含个人信息的改动。

GitHub 写入权限单独配置在各自环境。本项目不会分发维护者的个人令牌、学校登录资料或模型密钥。
