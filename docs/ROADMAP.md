# 后续开发计划

按独立 Issue 推进，不把计划文字当成已实现功能。当前版本状态见[能力与验证状态](CAPABILITIES.md)；v0.2.0 仍是未发布候选。

## v0.2.0 已完成（候选）

- 统一配置、路径与首次安装诊断：`python scripts/dev.py doctor` 与 `openthu-doctor` 分类报告环境、资源、认证与打包状态。
- 跨平台本地加密存储：Windows DPAPI 与 Linux 外部 `0600` 密钥文件；旧记录按原格式读取，跨平台不复制密文。
- 统一业务门面、29 个 MCP 工具兼容、CLI 的 `describe`/`health`/`query`/`agenda`/`dashboard`。
- 本地只读看板 API：回环绑定、本地会话、只读路由、限流与分页。
- 统一日程、增量变化与 ICS/Markdown/JSON 导出。
- 课程资料中心（宿主 API）：加密索引、跨课程检索、批量下载与 JSON 导出。
- 图书馆座位/研讨间与体育预约的专用办理适配（合成传输）；续借的计划与官方页面移交。
- 发行布局、确定性构建、`verify`/`install-check` 与旧状态迁移。

## 待办

1. **真实写入验收**：在本机 Windows 与真实账号下，按具体事项完成图书馆座位/研讨间、体育预约/取消、续借和作业提交的读取、执行、付款/审批与结果核对；公开只写脱敏摘要。
2. **个人课表、考试、成绩**：先取得可信来源与字段映射，再实现只读适配；教学日历不能代替课表或考试表。
3. **作业提交**：核对上传、草稿、正式提交、撤回和结果查询的官方接口与权限；没有契约时保持阻塞。
4. **模型图片协议**：核对学校模型服务的图片输入协议、大小与类型限制，补齐协议档案后再启用。
5. **亲友入校**：核对当前官方入口、字段、申请记录与审批语义，再设计专用只读/办理适配；公众参观保持独立能力。
6. **Linux 生产认证与桌面密钥环**：在保持“缺密钥拒绝写入”的前提下评估桌面密钥环；不得用明文落盘绕过 Windows 依赖。
7. **更多只读来源**：校内通知、云盘、培养方案等另建独立需求，先确认来源和权限。
8. **推送与通知**：增量事件本版只输出结构化结果；微信或其他渠道由外部工具在取得对应授权后处理，不在后台自动接力。
9. **原生移动体验、OCR/录音、课程知识库与适配生态**：本版之后单独规划。

每项交付包含代码、必要测试、当前验证级别、已知限制、回滚方法和下一位负责者。真实创建、取消、提交或付款始终需要针对该笔事项的明确授权。
