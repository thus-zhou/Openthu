# Hermes 执行启动说明

本方案包已经准备好，但尚未启动任何升级实现。使用者明确让你开始后，按以下方式连续推进。

1. 找到现有 Openthu 工作副本，先检查未提交内容、当前分支及远端。保留 PR #2 安装诊断成果，读取主分支最新 AGENTS.md 与批次约定；合入时核对冲突，不强制重置或覆盖。
2. 读取 00-总控与批次调度.md、01-参考依据与方案取舍.md 和 1.1 模块。第一批确认基线后，将这套方案按原编号纳入版本集成分支的 plans/v0.2.0，保留字数校验范围与来源。
3. 先完成 1.1，再开展第二批。任意后一批都以前一批全部验收并回接为前提。只有一个执行者时可以同批逐个完成；有经授权的多个执行者时，严格按文件负责范围、独立工作区与独立环境并行。
4. 每个模块只使用自己的方案文件、总控和已冻结输入，实施步骤、测试、异常与回退都写在正文中。按完成标准落实，不将模拟、缺来源或未启用能力记成实际业务完成。
5. 模块完成后提交、推送和更新版本清单，继续同批或下一批，不新开模块 PR，不因为一个小模块通过就结束完整升级。整个版本原则上复用原 Draft PR #2。
6. 条件适配缺可靠来源时，记录明确缺失项并继续独立模块。到整体验收仍不满足承诺范围时保持候选，交使用者决定补证据、延期或范围调整，不自行删减目标。
7. 遇到具体难题，按人工接力规范保存代码、复现、尝试和下一步，把需要 Codex 处理的范围交给使用者；不自动调用另一个 AI，也不发送未经授权的消息。
8. 第一至第七批完成后，由 8.1 串行形成完整候选。只在整体门槛满足时将同一个版本 PR 转为交审；第九批由 Codex 独立审查、合并和发布，Hermes 不提前发布正式版本。
9. 会话因运行限制停止前保留模块、步骤、分支、提交、验证状态和下一条动作。下次继续使用原版本计划，不重起小任务、不重复派发未知业务。

整个实施过程不需要现场演示、录像或真实校园交易作为通过条件。不得把使用者学校密码、Cookie、模型凭据或个人业务记录复制到方案包、测试夹具和公共仓库。
