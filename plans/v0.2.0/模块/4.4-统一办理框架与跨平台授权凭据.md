# 4.4 统一办理框架与跨平台授权凭据

版本目标：Openthu v0.2.0｜批次：4｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

在既有一次执行与事后核对框架上补齐跨平台宿主授权、状态恢复和副作用边界，使新增作业提交及续借能够复用统一机制，而不是各自绕过通用保护发送请求。

必须先取得第3批全部模块（3.1、3.2、3.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

actions.py、action_store.py、action_recovery.py、browser.py 的办理部分及新增 consent 模块；具体学校请求由第五批适配器负责。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 先审查现有准备、执行、结果查询和 RequestGate 的行为，保留已验证的不重放原则。将计划准备、上传产生草稿、正式提交、取消及退款核对分成可辨认阶段，任何会改变学校状态的步骤都必须进入明确授权的请求序列。

2. 定义可信宿主授权对象，绑定计划、账号域、业务摘要、适配器版本、有效期和一次随机挑战。MCP 中的说明字符串仍只记录用户意图，不能生成有效授权；网页内容、模型输出和普通环境变量均不能成为授权后门。

3. 保留 Windows 现有确认方式，Linux 提供本机交互确认入口或受控宿主签发接口。签发材料与业务状态一起加密保护，授权值不通过普通日志、公开报告或 URL 传递；没有可信宿主时返回需要使用者操作，绝不自动同意。

4. 统一计划与记录的状态转换，明确准备、待官方处理、派发中、未知、待审批、待付款、成功和失败的进入条件。每次转换采用带修订号的原子更新；执行前保存派发意图，保存失败时必须在请求发出前停止。

5. 预检必须重新读取关键条件，并精确比较资源、时间、成员、文件哈希、费用和规则。认证性令牌允许正常刷新，但业务内容变化必须重新准备。多请求按顺序匹配方法、路径、参数、请求体及来源框架，禁止同域整体放行。

6. 为上传和多阶段动作增加副作用清单，记录每一步是否确定未发出、已发出或结果未知。不能在超时后自动重复上传，也不能假定关闭页面就撤销了草稿；平台支持清理时仍作为单独具体动作核对与授权。

7. 完善恢复和撤销语义，技术回退只切换代码与本地指针，不代替真实业务取消。取消预约、撤回申请、删除附件和退款各自属于平台业务；没有适配契约及授权时只保留未决记录与官方入口。

8. 将事件与清洁的公开摘要提供给后续客户端，内部日志保留必要核对数据，外部只返回脱敏结果。验证取消、进程死亡、并发执行和存储失败不会扩大重试；框架完整并不自动证明某个学校写接口已经完成。

## 四、数据与接口约定

授权对象与操作编号不是平台幂等键，二者都不能推断学校一定支持防重。结果必须包含业务状态、结果核对等级、来源时间和可继续查询的标识。对同摘要的未决计划返回既有记录，终态重查不得重新派发。

## 五、异常、退化与兼容

缺授权、授权不匹配、计划过期、预检变化、锁冲突、加密失败和远端未知分开处理。只有有证据证明请求尚未发出时才使用未派发分类；无法判断时保存未知状态并提供核对入口，禁止用重试掩盖日志不确定性。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 把授权对象用于另一账号、另一计划或不同文件哈希时必须拒绝。
- 同一计划并发执行多次，合成远端最多收到一次既定派发。
- 请求已发出但响应丢失时，重启后只核对记录，不再次发送。
- 在派发日志保存阶段注入磁盘失败，远端请求计数必须为零。
- 预览后改变费用、成员、日期或附件，旧计划必须失效。
- 关闭可写开关后，已有事务的结果查询和恢复仍须可用。
- 普通浏览器控件和模型文本不能伪造宿主确认或开启通用写窗口。
- 代码回退和本地日志清理都不得自动发起真实业务取消。

## 七、回退与恢复

先禁止新计划和新派发，再保留当前事务读取及核对能力。回退必须保留能识别新格式的恢复运行时、密钥和未决日志，不恢复历史同域放行逻辑，不删除未知记录换取表面干净。

## 八、交付、回接与结束条件

交付授权协议、状态转移表、精确请求门禁和崩溃恢复测试。只有这些公共机制通过后，第五批学校办理模块才可接入；适配器不得自行复制一套弱化版授权逻辑。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
