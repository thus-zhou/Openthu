# 4.3 图书馆体育查询一致性与规则读取

版本目标：Openthu v0.2.0｜批次：4｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

加固现有图书馆、空间和体育只读来源，统一日期、分页、费用与资格说明，为后续办理提供可靠预检输入，同时保证查询功能在写入模块停用时仍可独立使用。

必须先取得第3批全部模块（3.1、3.2、3.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

library.py、spaces.py、sports.py 及相关只读解析测试；写适配器由第五批负责，browser.py 不在本模块修改范围。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 盘点馆藏、单册、借阅、数据库、座位、研讨间、体育项目、余量及订单的现有操作，建立输入输出与实际来源的对应表。针对已知部分结果和平台分页限制保留明确说明，不以统一接口为由删除站点特有边界。

2. 规范日期和资源选择，优先采用稳定编号，名称歧义返回候选。座位沿用平台提供的完整时段，研讨间按时间交集检查；体育保留场景、房间、场地和场次的层级，不把场馆总容量解释成某个场次仍有余量。

3. 统一实时余量读取策略，新查询必须获取当前来源，游标仅续读原快照。余量、开放状态、本人资格和费用分别表示，不因页面显示空闲就推断可预约；来源缺少其中一项时保持未知，并列出后续准备需要补查的项目。

4. 对本人记录分页逐页核对上游计数、重复页和状态筛选。座位历史的固定页长、研讨间默认状态范围以及体育订单窗口都写进结果；缺页时返回部分状态，不能从筛选后的空结果断定本人没有预约。

5. 将学校规则按来源、原始字段、单位和检查时间保留，明确分钟、日期、金额分及人数含义。对于含糊单位和未知枚举停止推算，取消期限、费用和处罚提示不得套用第三方常见规则或上一版本的固定常量。

6. 完善书目、借阅和数据库读取，续借资格仅作为后续写入预检信息。馆藏可借状态、个人借阅资格和第三方电子资源授权分开；查询模块不主动续借、不访问未经核对的校外资源，也不转发学校 Cookie。

7. 为办理模块提供稳定的预检读取对象，保留平台记录号、资源标识、状态及可核对字段。公共预览只显示必要摘要，其他人的占用信息应去除身份和主题；本人业务原值仅在受保护状态中供后续核对使用。

8. 针对接口改版、学校维护和独立登录更新解析器错误路径，保持旧操作名与参数兼容。交付只读契约和案例供第五批消费；需要改变公共 schema 的建议登记到集成清单，由 6.1 统一接线。

## 四、数据与接口约定

预检对象把资源、时间窗口、余量、资格、费用和规则拆成独立字段，并为每项标识来源及是否已确认。订单保留预约、审批、付款和退款的原状态与规范映射，续借提示不提前改变借阅到期字段。

## 五、异常、退化与兼容

遇到日期无效、资源不唯一、站点关闭、分页循环和业务拒绝时给出不同原因。解析失败不得回退成空数组，规则缺失不得默认为无限制；限流时遵守来源等待提示，取消后不继续后台翻页。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 座位区域容量较大但目标时段已满时，输出不得混淆两个数值。
- 研讨间空闲但人数不符时，空闲与不可准备必须同时正确表达。
- 同名场地属于不同项目时，应返回候选而不是任意选一个。
- 本人订单读取到重复页或缺少末页时，应保留部分结果和续页信息。
- 费用原值以分计时，展示和后续预检不得出现百倍换算错误。
- 查询未知退款、审批状态时，不把它们映射成成功或已经到账。
- 占用记录包含合成人员信息时，公开结果必须去除无关身份。
- 停用所有新写入功能后，原有只读入口仍应按原契约工作。

## 七、回退与恢复

可按服务单独关闭新版解析并保留旧查询入口，但已发现不安全或错误的映射不能恢复为默认。历史缓存保留版本和原时间，回退不能将上次余量展示成当前可用。

## 八、交付、回接与结束条件

交付完整只读操作矩阵、预检对象、规则单位说明和退化行为。必须证明读取结果能支撑后续精确核对，同时对缺失资格和未读全记录保持诚实状态。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
