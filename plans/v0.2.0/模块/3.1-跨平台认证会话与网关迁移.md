# 3.1 跨平台认证会话与网关迁移

版本目标：Openthu v0.2.0｜批次：3｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

把安全存储接入现有 Python 与 Node 运行链，解除会话、浏览器、待办和事务直接依赖单一平台函数的问题，同时保持既有 Windows 登录和旧会话的可恢复性。

必须先取得第2批全部模块（2.1、2.2、2.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

gateway.js、gateway_client.py、session-store.js、session-policy.js、browser.py 的会话部分、auth.py 及 runtime/windows 兼容包装；事务业务逻辑留给 4.4。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 列出认证凭据、门户 Cookie、网络学堂会话、浏览器状态、模型令牌和事务日志的全部读写点。建立调用图，识别默认参数绑定旧加密函数的地方，避免只替换模块变量却遗漏已捕获的函数引用。

2. 使用前批冻结的提供者和路径解析器替换直接平台调用。旧函数签名保留兼容包装，新的存储后端通过明确依赖注入选择；Linux 缺密钥时在首次需要保护状态的操作上失败，不影响纯静态目录和离线开发。

3. 调整 Node 到受控加密子进程的通信，绑定请求编号、长度、超时和取消。只允许既定封装动作，拒绝客户端提交任意程序或文件路径。任何解封内容不得转发为 MCP 返回值，调试输出只能记录阶段、错误类别和条数。

4. 适配上游认证组件时通过项目包装层控制凭据提供者，不直接改动第三方源文件。保留真实账号状态在原有环境的默认行为，Linux 独立配置必须由使用者建立，不自动从 Windows 导出密码、Cookie 或受保护设备信息。

5. 对旧会话进行先识别、再读取、再验证、最后写新格式的渐进迁移。账号、服务、用途及 Cookie 作用域全部核对；旧密文在新格式完整保存前保留，不跨系统尝试绕过 DPAPI，也不把无法解密理解为用户已经退出登录。

6. 保持单进程队列和跨进程锁的顺序，文件锁只包住本地读改写。认证失败恢复次数继续受限，权限拒绝、额度不足和不确定的网络结果不触发重复生成或写入；新提供者不能扩大已有自动重试范围。

7. 统一浏览器上下文导入与回存，精确保留过期时间、域名、路径和按来源隔离的应用状态。持久化失败要返回明确状态；浏览器关闭或账号切换时清理内存引用，不能把另一个服务的状态当成当前服务的登录证据。

8. 补充两平台和多进程的合成认证链测试，使用假的校园传输层验证跳转、会话更新、密钥缺失和取消。无需学校账户即可验证控制逻辑；二次认证仍返回官方需要使用者处理的状态，不承诺无交互完成所有登录。

## 四、数据与接口约定

会话包继续保留账号绑定、服务来源、Cookie 属性、应用状态、修订号和检查时间。迁移结果额外记录原格式、目标格式与是否已保存，不在公开结果附旧文件位置。认证状态、页面可读状态和业务成功状态保持独立，不能通过一次登录统一置为全部可用。

上游保留的旧明文令牌兼容不能成为新版默认生产路径。包装层应区分安全读取、用户明确要求的本机迁移和禁止自动导入；迁移前先检查并保护原件，不能把旧明文状态复制到云端来获得跨平台可用。

## 五、异常、退化与兼容

密钥错误、账号不符、旧格式损坏、状态竞争和认证失败分别处理。恢复阶段发现远端结果不确定时先核对状态，不重放。加密子进程失联后仅使当前调用失败，下一次独立调用可重新建立，不把前一次请求偷偷发送第二遍。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 旧 Windows 密文成功读取后，新旧状态都应保留至新写入核验完成。
- Linux 缺主密钥时静态目录可用，涉及持久会话的操作必须给出精确错误。
- 同一服务在两个进程更新不同 Cookie，应正确合并或明确报告冲突。
- 把账号 A 的会话用于账号 B，必须拒绝且不得覆盖 B 的有效状态。
- 模拟浏览器保存失败，返回结果应说明未持久化，不能继续声称已保存。
- 在认证恢复前后取消请求，确认没有重复模型生成或校园写入。
- 构造服务跨域和过期 Cookie，确认不会因迁移放宽注入范围。
- 检查子进程标准输出边界，外层 MCP 日志不得出现解封内容。

## 七、回退与恢复

关闭新会话写入并切回兼容包装，保留新格式读取工具及旧密文备份。若存在新格式未决事务，不能回退到无法读取它们的运行时；账号需要重新认证时明确提示，不删除状态强迫静默重建。

## 八、交付、回接与结束条件

交付读写点清单、渐进迁移记录、受控通信协议和平台测试结果。旧客户端查询应保持行为，真实生产 Linux 加密路径必须与合成夹具分离，所有平台差异通过同一接口表达。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
