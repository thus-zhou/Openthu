# 2.3 校园来源证据与业务数据契约

版本目标：Openthu v0.2.0｜批次：2｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

先明确每项新校园能力依据什么来源、返回什么数据以及怎样证明完整，尤其约束课表、考试、成绩、作业上传、续借和多模态传输，避免后续模型凭经验猜测学校接口。

必须先取得第1批全部模块（1.1）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

contracts/v0.2/sources、docs/contracts、合成来源夹具和证据清单；不修改运行时查询注册表。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 建立现有服务与计划新增服务的来源矩阵，区分公开入口、需要认证的入口、可复用协议代码和仅供测试的合成样例。记录来源负责人、核对时间、适用版本与取得方式，不把第三方教程或历史通知作为当前接口成功契约。

2. 对现有 learn、library、sports 和模型模块逐项提取真实代码已经依赖的字段、分页、错误及状态映射。把说明与实现不一致的地方列为待纠正项，特别标明早期文档中的空适配器描述与当前已注册办理模块之间的差异。

3. 为课表、考试和成绩分别建立来源任务，核对学期标识、课程标识、时间精度、成绩含义、分页与权限。不得从教务日历推导完整个人课表，不按缺失成绩计算零分，也不假设不同来源的同名课程一定是同一门课。

4. 为正式作业提交提取上传、草稿、最终提交、版本覆盖和结果查询的边界。任何会产生服务器状态的上传都算写入，不允许在准备预览时偷偷完成。续借则分别记录资格提示、执行接口和新的到期记录，不能把允许续借当成成功回执。

5. 为图片模型能力核对实际请求格式、支持模型、媒体限制和响应形式；官方目录仅列支持图片时仍不足以证明当前代理可传输图片。没有可验证协议时提供明确不可用原因，禁止试发个人图片探测格式。

6. 建立事件、课程、资源、成绩、订单和附件的规范结构，保留原始来源字段与标准字段之间的映射。字段缺失要有未知语义，数组空值必须绑定来源成功证据；正式枚举、接口路径和请求体只登记已有可靠依据的内容。

7. 证据在公开仓库只存结构、说明、合成样例和摘要哈希。原始个人响应留在使用者控制的环境，不复制到云端或公开日志。若需要本机读取来补足依据，生成最小化问题清单供 Codex 人工接手，不在本方案中安排真实交易来制造证据。

8. 为每个条件适配给出启动结论：契约足够可实现、缺关键依据暂缓、账号权限不足或来源不可用。后批必须读取该结论；缺依据时仍可完成内部模型和失败路径，但不能把未启用的生产适配打勾为完整功能。

## 四、数据与接口约定

来源证据记录至少含 source_id、服务、操作、证据类别、版本、检查时间、字段映射、分页规则和未决问题。学业条目分别保留源编号和课程关联；数据模型采用可选字段表达缺失，不在规范化阶段加入推算分数、默认时间或虚构业务编号。

## 五、异常、退化与兼容

发现网页壳、认证重定向、同名多入口或返回结构变更时停止确认该契约。合成夹具只能证明解析器行为，不能提升证据等级。没有公开或经授权可取得的来源时保留阻塞，后续执行者不得换成未经审查的第三方抓取方式。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 把登录页返回二百状态作为样例，契约必须识别它没有业务数据。
- 为同名课程、不同学期和缺稳定编号设置映射样例，确认无错误合并。
- 分别验证全量空结果、第一页为空但仍有下一页以及来源失败三种语义。
- 将上传成功、草稿保存和正式提交成功分别定义，确认不会折叠为同一状态。
- 对续借资格通过但执行失败定义独立结果，不能提前修改到期时间。
- 模型目录与实际图片协议不一致时，能力结论必须保持未核对。
- 扫描证据文件，确认仅含合成结构和公开说明，没有个人原值。
- 检查每项计划新能力都有负责人、启动结论和可追溯依据。

## 七、回退与恢复

证据结论调整采用新版本记录并保留变更原因，不能覆盖旧结论使既有测试失去来源。若某来源撤回或改版，禁用受影响适配，其他独立服务继续使用此前已验证的契约。

## 八、交付、回接与结束条件

交付来源矩阵、结构契约、边界样例及条件适配启动表。没有来源的能力必须在总清单中醒目标记；下一批收到的应是可执行的字段和状态约定，而不是一句“后续自行研究接口”。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
