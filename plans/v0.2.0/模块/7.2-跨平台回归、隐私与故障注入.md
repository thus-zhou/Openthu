# 7.2 跨平台回归、隐私与故障注入

版本目标：Openthu v0.2.0｜批次：7｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

建立覆盖新旧能力的版本级检查，重点验证跨平台存储、真实生产边界、无意副作用、恢复能力和发布内容，避免模块各自通过后集成版本仍出现隐私泄露或数据语义错误。

必须先取得第6批全部模块（6.1、6.2、6.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

新增 tests/release_regression、tests/security_regression、CI 工作流与验证报告生成器；不修改同批前端资源和文档正文。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 先汇总各模块已有测试与契约断言，建立功能到用例的映射，保留 v0.1 的兼容基线。新增数量只作为记录，不把测试条数作为质量目标；删除旧测试或修改断言前必须解释行为变更和替代证据。

2. 为 Windows 和 Linux 分别组织生产后端与合成传输测试。Linux 应测试新真实加密算法与权限边界，同时用假校园传输避免真实账号；测试编码器仍只在显式测试路径，不允许把生产入口切成弱保护来让 CI 通过。

3. 建立异常注入矩阵，覆盖超时、断流、取消、锁冲突、进程退出、磁盘不足和部分写入。所有可能有副作用的路径都记录请求计数，验证准备不上传、未知不重发、恢复只核对，不能只检查最终返回的状态字符串。

4. 建立敏感标记集，向合成姓名、账号、路径、主机、令牌、文件和图片注入可识别值，扫描标准输出、异常、报告、交接、缓存及候选包。允许的私人状态必须确实受保护，公共输出与发行资产不得出现这些原值。

5. 检查查询完整性、时间精度、稳定编号、增量删除和日历导出，构造跨午夜、来源失败、缺页与同名记录。特别验证不同账号和不同学期之间的缓存、游标、媒体引用和本地看板会话不能串用。

6. 调整 CI 只使用可复现的受支持系统及固定运行时范围，必要浏览器由明确步骤安装。每个检查输出版本、范围和通过或失败摘要，不上传原始个人日志；不使用 pull_request_target 等方式执行未受信贡献并赋予仓库秘密。

7. 把候选包检查、依赖审计和隐私扫描接入版本门禁，默认不包含学校实账号、付费模型或真实事务。CI 缺外部条件时标注缺口，不能把不运行的核心测试统一跳过后仍宣称该平台全部可用。

8. 为集成批提供可机器读取的结果，指出失败所属模块和最小复现。若需要修复实现，应通知其负责人并在独立修复提交中处理，不能在测试模块偷偷重写生产业务或弱化安全断言来追求绿灯。

## 四、数据与接口约定

验证报告包含源码提交、契约版本、平台、用例范围、通过失败跳过、跳过原因及副作用计数。跳过数量必须可解释，未执行与通过分开；发布用摘要只含安全字段，原始失败材料留在受控环境。

## 五、异常、退化与兼容

任何泄露、未经授权写入、重复派发、旧接口破坏和不可恢复状态都属于阻断问题。依赖服务暂时失败不能被通用重试隐藏；确属测试本身错误时修正夹具并保留原因，不删除事故样例。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 秘密标记进入公共输出或归档时，门禁必须稳定失败。
- 生产入口尝试使用合成编码器时，应有测试确认它无法启用。
- 上传已发出后响应丢失，重复调用不得增加远端写计数。
- 账号切换与游标跨范围使用应明确拒绝，不能返回旧数据。
- 损坏加密状态、轮换中断和磁盘失败后应保留可恢复的最后有效记录。
- 来源缺页不能产生大量删除事件，也不能把失败显示为没有待办。
- 从干净 CI 环境启动时，不应依赖开发机器的路径和用户配置。
- 关闭某个可选新功能后，旧工具目录与原主要查询仍可使用。

## 七、回退与恢复

测试和 CI 规则可以回退到上一有效版本，但必须保留已发现的安全回归用例。若新检查揭示真实缺陷，应阻止候选发行而不是恢复一个忽略问题的旧规则来绕过门禁。

## 八、交付、回接与结束条件

交付覆盖矩阵、两平台报告、敏感标记扫描和故障注入结果。第八批只能使用与其候选提交一致的证据，不能拿另一分支早先的通过结果证明当前版本可发布。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
