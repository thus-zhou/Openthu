# 2.2 跨平台加密存储与密钥生命周期

版本目标：Openthu v0.2.0｜批次：2｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

建立 Windows 与无桌面 Linux 都能使用的存储抽象，保护凭据、会话和业务状态，同时保留原 Windows 用户才能解密旧数据的现实边界，避免把公开机器属性误认为秘密密钥。

必须先取得第1批全部模块（1.1）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

新增 src/thu_assistant/secure_store/ 及独立安全测试；不修改 vendor/madmodel-proxy 原始代码。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 先核对现有上游 Linux 凭据实现及 Openthu 的直接 DPAPI 调用。上游使用机器标识和用户信息派生密钥，不等于本项目全部状态已跨平台，也不足以作为独立秘密保护的唯一依据；记录兼容边界，不直接复制该机制作为新的默认方案。

2. 定义统一存储提供者，包含封装、解封、健康检查、密钥标识和格式版本。Windows 默认继续使用当前用户 DPAPI；Linux 无桌面模式使用外部秘密文件提供随机主密钥，桌面密钥环作为可选后端，不让云端运行依赖图形会话解锁。

3. 采用成熟认证加密接口，推荐 cryptography 的 AESGCM，不自行编写密码算法。生成独立随机密钥和每次唯一随机 nonce；把账号摘要、服务、用途、格式版本和修订信息绑定到附加认证数据，密文与元数据必须一起接受完整性验证。

4. 密钥文件与数据目录分离，配置只保存位置引用。校验所有者、权限、普通文件属性和符号链接，权限不符就拒绝使用；不得把密钥放进配置样例、命令行参数、诊断输出或与密文一同上传的归档，机器标识不能替代随机秘密。

5. 设计带版本的密文封套及原子落盘流程，分别处理空输入、截断、损坏、账号不匹配、未知用途和缺少密钥。读取失败应保留精确原因，不按空记录处理；加密失败不创建明文临时副本，覆盖失败不得破坏最后一份有效数据。

6. 设计密钥轮换与迁移预览，逐条解封、重封、核验后再切换有效指针。旧密钥及旧密文在确认完成前保留受保护备份；中途崩溃可以继续或回退，不能因为部分成功就删除旧状态，也不把凭据复制到另一台机器当成自动迁移。

7. 提供供 Node 私有子进程边界使用的封装接口，协议只暴露固定动作与有界载荷。解封后的数据仅在受控管道与进程内存中传递，不进入 MCP 公共输出；子进程环境实行最小继承，避免主密钥被无关工具和构建步骤获得。

8. 为后续会话、事务、媒体和事件缓存提供统一测试夹具。生产实现与合成编码器在导入路径和配置上彻底分开；测试可以显式注入假存储，正式入口不得存在一个环境变量就能启用明文或假加密的后门。

## 四、数据与接口约定

密文封套包含格式、后端、密钥编号、nonce、附加数据摘要与密文，账号摘要不能还原原始账号。旧 DPAPI 数据采用显式格式识别；跨系统无法解密时返回需要重新建立会话。修订字段用于并发校验，不宣称仅靠密文本身就实现抗完整文件回滚。

账号域使用随机稳定标识及受保护映射，或经审查的独立用途密钥方案，不能把低熵账号的无密钥裸哈希宣传为匿名化。账号映射的备份、轮换和丢失后果必须与会话一起说明。

## 五、异常、退化与兼容

缺密钥、权限错误、解密失败、格式损坏与账号不匹配分别建立错误码。错误不得包含密文原文、密钥内容和用户路径。无法确定旧数据状态时保留原件并停止写入，不能以清空缓存代替解决问题。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 同一记录连续加密应得到不同密文，并能在同一合法提供者下恢复。
- 修改 nonce、密文、服务域或账号域，解密必须失败且不返回部分明文。
- 移走密钥、扩大文件权限和替换为链接，初始化均应拒绝。
- 在写入、刷盘和切换指针各阶段注入崩溃，最后有效记录必须可恢复。
- 模拟轮换一半失败，旧密钥和旧封套仍可读取未迁移部分。
- 跨账号及跨用途读取同一密文，确认不能发生状态串用。
- 检索临时文件、异常和测试报告，确认没有秘密与明文业务内容。
- 验证生产入口在未配置 Linux 提供者时明确失败，不能加载测试编码器。

## 七、回退与恢复

先停止新写入，再切回上一个已验证的提供者与指针；保留未决事务使用过的密钥及格式支持。只有全部读取核验完成后才能清理旧加密材料，回退代码不撤销已经发生的远端业务。

## 八、交付、回接与结束条件

交付提供者接口、两平台后端、轮换与恢复流程及威胁边界说明。必须通过篡改、权限、并发和崩溃测试，不能只验证一次加解密往返；新增密码依赖的版本和许可证由发行模块固定。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
