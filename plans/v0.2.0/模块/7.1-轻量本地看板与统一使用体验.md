# 7.1 轻量本地看板与统一使用体验

版本目标：Openthu v0.2.0｜批次：7｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

把已经具备的校园查询整合为可日常使用的本地看板，围绕课程、截止日期、借阅、预约和资料提供清楚的状态与检索体验，同时保证界面不会隐式执行真实校园写入。

必须先取得第6批全部模块（6.1、6.2、6.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

新增 src/thu_assistant/web_assets/ 与前端单元或契约测试；不修改本地 API、业务门面或包元数据。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 先按冻结 API 和合成样例完成信息结构，划分总览、课程、资料、日程、借阅预约和健康六类页面。界面只依赖规范展示对象，不读取源码目录、会话文件或第三方认证存储，也不直接请求学校接口。

2. 使用简单可维护的本地静态资源，首版不依赖外部 CDN、远程字体或第三方分析服务。所有资源通过自身来源加载，离线也能打开空状态与帮助；样式、脚本和资源目录按发行清单约定命名，避免新增不可追踪的构建链。

3. 总览卡片同时显示来源时间、实时或历史状态、读取完整性和下一步。未登录、来源失败、没有记录与未启用能力使用不同文案，不以一个空白图标代表所有情况，也不让失败卡片使其他服务结果全部消失。

4. 课程与资料页面提供学期、课程、类型和关键词过滤，资料选择与导出范围明确可见。保留已选择项目和分页状态，跨页选择须有稳定编号；新查询参数改变时清理旧快照选择，避免把不同条件的文件混成一次批量操作。

5. 日程采用可切换时间线和列表，区分日期级、精确时间、逾期和冲突提示。课程周期缺少校历时显示原周期及限制，成绩默认不进入总览；需要查看敏感详情时使用明确的本地操作和最小字段投影。

6. 借阅和预约页面读取既有记录及状态，展示官方安全入口与可核对信息。首版看板不提供预约派发、正式交作业、付款或密钥编辑按钮；相关需求引导到既有受控工具流程，不能暗藏在普通刷新或链接点击中。

7. 对输入、标题、来源文本和链接进行严格展示转义，设置合适的内容安全策略与可访问语义。键盘能够完成导航和筛选，窄屏不遮挡错误提示，加载与取消有明确反馈，避免用户因没有响应而连续重复点击。

8. 在无校园账号的自动化环境中使用合成 API 跑完整界面流程，检查加载、部分失败、会话失效和关闭。只提交必要资源与测试，不把调试截图、浏览器状态或本机启动凭证加入仓库；后续由集成批验证完整安装包中的界面资源。

## 四、数据与接口约定

组件只消费固定版本的展示对象，默认不暴露个人账号、原始成绩、成员标识和文件路径。导航不带访问令牌，外部链接需要安全协议和来源检查；分页与来源状态由 API 明确提供，不由前端猜测。

## 五、异常、退化与兼容

API 失联、会话过期、单源失败、历史缓存和功能未启用分别给出可执行提示。前端不能通过关闭鉴权或改用学校裸接口自救，错误上报只包含页面、组件和安全分类，不发送用户数据到外部分析平台。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 空记录、未登录和来源故障三类页面应可直观看出差异。
- 合成标题含脚本、HTML 和危险链接时，不得被当作可执行内容。
- 分页后改变筛选条件，旧选中项与旧游标不能误用于新下载计划。
- 一个服务超时，其余页面内容仍能展示并可取消加载。
- 键盘导航、窄屏和较长中文标题不能隐藏核心状态和操作说明。
- 检查前端网络，确认没有 CDN、统计上报或直接学校请求。
- 普通刷新、导航和查看详情不能产生预约、提交或模型生成副作用。
- 会话关闭或账号切换后，页面不得继续显示另一账号缓存的敏感详情。

## 七、回退与恢复

停止看板入口即可保留原 MCP 和 CLI；移除静态资源时不删除本地状态或用户下载。出现前端兼容故障时提供文字提示和命令入口，不要求使用者清空全部认证数据。

## 八、交付、回接与结束条件

交付完整只读页面、状态文案、无外部依赖的静态资源和自动化检查。看板需能连通实际业务门面，同时保留无账户下的准确状态，不能只交一套静态假数据页面。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
