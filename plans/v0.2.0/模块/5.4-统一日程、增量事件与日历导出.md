# 5.4 统一日程、增量事件与日历导出

版本目标：Openthu v0.2.0｜批次：5｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

把作业、借阅、预约与已核对的课表考试整理为可追溯日程，增加时间线、冲突提示、变化事件和标准导出，同时保持插件按需运行，不引入后台守护与默认消息发送。

必须先取得第4批全部模块（4.1、4.2、4.3、4.4、4.5）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

todos.py 及新增 events、calendar_export、snapshot_diff 模块与测试；不修改各站点适配器或实现外部消息机器人。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 接入学业适配的能力表，只有可用且被明确选择的来源进入聚合。保留原作业、借阅、图书馆和体育来源，考试与课表分别提供筛选；成绩默认不进入待办或公开摘要，避免把所有新学业数据混在一个默认结果里。

2. 统一稳定事件编号和来源版本，保留日期精度、时区、原始状态及检查时间。作业截止、借阅到期、预约区间和周期课程分别建模，不用同一个截止字段强行表示；取消或改期仍保留可追踪的事件身份。

3. 增加临近截止、逾期、无日期和按来源分类的视图，使用同一查询时刻计算窗口。时间冲突仅对具有可信起止时间的区间判断，全天事件、未知时间和缺校历的周期课表不得被当成精确时间冲突。

4. 建立账号、来源、参数和规范版本绑定的增量快照。变化类型包括新增、修改、明确取消与来源不可用；只有前后均完整且可比较时，消失记录才可以判断删除，不把分页失败或来源断线变成所有事件已取消。

5. 增量查询使用不透明游标，带格式版本、范围和到期规则，不直接把上次时间戳当成可靠断点。事件有稳定变更编号以便外部消费去重；提供事件不代表已推送，不记录没有真实消费证据的已送达状态。

6. 实现日历文件导出，遵守 iCalendar 的转义、换行折叠、时区及全天日期语义。稳定 UID、更新序号和取消状态需可重复导入，不能每次导出生成新事件；文件导出前明确选择范围，不能默认包含全部个人日程。

7. 提供 Markdown 与结构化摘要导出，默认使用脱敏字段和来源链接。导出在本地明确目标执行，禁止远端标题造成公式、脚本或路径注入；HTML 和看板展示另做文本转义，不能把同一份未转义文本直接到处复用。

8. 对外只提供可按需调用的变化结果或本地导出，不实现微信凭据管理、自动发消息、后台轮询或自动预约。Hermes 等外部工具可以在各自授权下消费结果，插件不因此取得新的消息发送权限。

## 四、数据与接口约定

事件对象包含稳定编号、来源、源编号、时间精度、业务状态、检查时间及完整性。增量游标绑定账号和查询范围，冲突结果包含参与事件和依据；导出只消费规范事件，不重新抓取学校或偷偷补全未知字段。

## 五、异常、退化与兼容

快照过期、范围变化、来源失败、数据不完整和模型版本变化分别使增量查询重建或返回不可比较。导出失败不留下可被误认为完整的半文件，取消请求不把尚未消费的事件标记为已处理。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 同一快照重复比较时，不应重复生成语义相同的新事件。
- 来源断线或少读一页时，原有事件不得全部变成已删除。
- 跨午夜续页和夏令时样例应保持原查询窗口与正确时区。
- 只有日期的截止事件导出后，仍应是日期级而不是午夜时间。
- 重复导入同一日历文件应更新原 UID，而非生成重复事件。
- 两个来源的同名事项缺少关联依据时，必须保持独立身份。
- 含脚本字符、换行及特殊分隔符的标题不能破坏导出结构。
- 监测网络与进程，确认没有后台轮询、模型请求和消息发送。

## 七、回退与恢复

关闭增量与新导出选项即可保留原待办聚合。旧快照与新格式分别隔离，回退允许明确游标失效；本地导出的日历文件属于使用者资产，不自动删除或远程撤销已经导入的事件。

## 八、交付、回接与结束条件

交付统一日程、冲突提示、可靠增量和两类导出。需要明确展示来源缺口与历史时间，不能将一个排序列表包装成已经具备自动提醒或全部考试覆盖的系统。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
