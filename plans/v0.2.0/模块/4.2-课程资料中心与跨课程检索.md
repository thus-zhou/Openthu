# 4.2 课程资料中心与跨课程检索

版本目标：Openthu v0.2.0｜批次：4｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

把已具备的课程、公告、作业附件和课件读取整合成可检索、可归档的资料中心，提供跨课程发现、明确选择和可靠下载，保留每份资料与原课程、公告或作业的关联。

必须先取得第3批全部模块（3.1、3.2、3.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

新增 src/thu_assistant/resources/、索引与下载清单测试；原下载核心仅通过既有接口调用，公共入口留给 6.1。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 定义资料来源集合，分别接收课程文件、公告附件与作业附件，保留源记录编号、课程、学期、标题及关联正文的读取状态。先建立索引，不因为发现附件就下载，也不让资料汇总隐式触发全学期文件抓取。

2. 建立跨课程元数据与已明确读取的公告正文检索，按学期、课程、类型、更新时间和关键词组合筛选。首版检索不宣称已读懂全部 PDF、图片和录音；没有解析内容时只检索已有元数据，并在结果中说明覆盖范围。

3. 本地索引按账号和学期隔离，持久内容使用加密存储。首版可对有界索引解密后在内存搜索，不在明文全文数据库保存个人课业记录；设置条数、体积和保留期限，避免为了搜索速度引入无法保护的新缓存。

4. 设计稳定的资源清单，区分同名不同编号、同编号不同版本及相同内容不同来源。来源更新时间不可靠时保留未知，通过已下载内容哈希识别重复；不能仅凭名称相同就覆盖或合并两个附件。

5. 提供批量选择与下载计划，预览文件数量、估计大小、目标目录和覆盖处理。选择确认后调用现有下载器，逐项记录成功、复用、失败与来源复核结果；部分失败不能把整个批次写成全部完成，也不能重复下载已成功的相同内容。

6. 归档目录使用安全课程和文件名，保留稳定编号避免重名，禁止远端标题生成上级目录或绝对路径。写入采用临时文件和校验后落盘，哈希冲突、磁盘不足和文件占用必须保留原文件；下载目录由使用者明确选择。

7. 提供资料摘要导出，默认仅导出选择的字段与来源链接，包含个人内容时在执行前明确提示范围。导出文件属于使用者本地资产，不自动加入仓库或上传模型；需要模型总结时由调用方单独选择资料与发起请求。

8. 实现索引刷新、删除本地缓存和下载记录查询，刷新过程保留原始检查时间与来源错误。给后续门面和看板提供不含真实文件路径的资源标识，预留将来内容解析的扩展字段，但不在本模块引入 OCR 或音频服务。

## 四、数据与接口约定

资源条目使用来源、源编号、版本与账号域组成逻辑键，下载清单另有本地清单编号和内容哈希。检索结果返回匹配字段、覆盖来源、总量是否已知、检查时间和续页信息；资源引用不是任意本地文件读取权限。

## 五、异常、退化与兼容

附件关联失效、课程重名、来源缺页、内容变化及存储失败分别报告。刷新失败时旧索引可在明确允许下读取并标记历史；不得把旧索引上的文件链接当成仍有效的下载资格，也不自动遍历私人目录补齐缺失内容。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 同名附件来自不同课程时，结果和归档目录都必须保留各自身份。
- 索引构建阶段拦截下载传输，确认没有隐式下载或上传行为。
- 只读取部分公告时，全文搜索结果应说明正文覆盖不完整。
- 批量下载中一项失败，清单必须保留其余成功项并可继续处理。
- 使用包含上级路径和保留设备名的标题，确认目录边界不被突破。
- 刷新后附件内容变化，应产生新版本而非静默覆盖已保存文件。
- 其他账号不能读取现有索引、资源引用和本地下载记录。
- 导出与错误报告不得附带未选择的课程内容或私人路径。

## 七、回退与恢复

停用资料中心不影响原课程文件列表和下载入口；保留使用者已经下载的文件。回退只处理新版加密索引和清单版本，不批量删除归档目录，也不把加密索引转存为明文方便旧版读取。

## 八、交付、回接与结束条件

交付统一资源模型、检索、批量计划、归档与刷新能力。验收以来源可追溯、选择范围明确和失败可恢复为核心，不能以建立一个空索引或展示几个模拟标题作为资料中心完成的依据。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
