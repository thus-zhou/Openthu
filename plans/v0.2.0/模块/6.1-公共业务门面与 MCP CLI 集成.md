# 6.1 公共业务门面与 MCP CLI 集成

版本目标：Openthu v0.2.0｜批次：6｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

把前几批完成的能力统一接到公共入口，保持现有二十九个 MCP 工具的兼容，落实能力启用、错误映射和命令行功能，使所有客户端通过同一业务语义调用已验收模块。

必须先取得第5批全部模块（5.1、5.2、5.3、5.4）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

mcp_stdio.py、queries.py 的注册部分、gateway.js 的分派接线、__main__.py 和公共 schema；其他模块停止修改这些共享入口。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 逐项核对前批交付的接口版本、依赖和启用状态，先生成注册清单再写分派。缺契约、缺提供者或未通过测试的能力不进入默认可用列表，不能因为代码文件存在就自动注册成生产功能。

2. 实现冻结的业务门面，将查询、健康、准备、执行、结果和取消映射到已有业务模块。门面负责账号域、请求范围和统一信封，适配器负责站点细节；本地看板与 MCP 不得各自再实现一套状态判断。

3. 扩展 describe_service 的能力说明和 query_service 的登记操作，保持原参数及结果字段可用。旧未知字段仍按规则拒绝，新参数应有明确默认值；不接受 method、headers、token 或任意上游 URL 作为万能接口后门。

4. 保持公开 MCP 工具名称与数量的兼容基线，新增学业、资源和续借等能力优先放入既有统一入口。确有不可兼容需求时先登记版本变更，不为了节省工具数量把写操作塞进只读 query_service。

5. 为模型媒体、资料导出与增量查询接入可选参数，明确每种操作的副作用和所需授权。用户文件引用经过专用边界，导出目标经本地路径规则校验，模型调用不会因普通列表查询自动发生。

6. 完善命令行入口，提供健康诊断、按服务查询、日程导出和启动本地看板等明确子命令。保留 openthu 及原清华助手、网络学堂命令兼容；旧命令帮助与输出字段变化要有迁移说明，避免脚本升级后悄悄执行不同操作。

7. 贯通进度和取消，将请求编号、队列、传输、媒体处理和存储清理绑定到同一次调用。取消不重放、错误不输出秘密，标准输出只包含约定的结构化结果；调试信息不破坏 MCP JSON 行协议。

8. 在不需要学校账户的环境中启动完整 MCP 和 CLI，枚举工具、描述全部服务并执行代表性合成查询。对有副作用的命令使用假适配验证授权序列，交付公共参数与门面接口供本地后台最终接线。

## 四、数据与接口约定

公开入口保留现有二十九个名称，新增操作具有固定参数 schema、读写属性、启用条件和结果版本。业务门面的实现遵守第一批冻结结构；错误映射保留原类别及安全的重试提示，不能把所有异常变成通用成功结果。

## 五、异常、退化与兼容

缺模块、版本不匹配、参数非法、能力关闭和认证要求分别处理。某一服务失败不应导致整个工具枚举进程崩溃；写操作永远不能因门面回退而绕过授权直接调用适配器。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 使用旧客户端参数调用原工具，必须保持结构与基本语义兼容。
- 枚举工具目录应维持约定入口，不因新增业务重复暴露一组工具。
- 未启用适配的调用应返回具体能力缺口，而非伪造空成功。
- 通过只读入口传入写字段、认证头或任意方法时必须拒绝。
- 模型图片和本地文件引用不得绕过媒体与路径校验。
- 取消排队及执行中的请求，确认没有额外派发或协议串行错误。
- 服务单点异常时，其他独立服务和健康描述仍可响应。
- MCP 标准输出、CLI JSON 和异常文本不得包含秘密或调试噪声。

## 七、回退与恢复

通过能力注册和开关逐项撤回新操作，保留旧工具与恢复入口。门面版本回退前核对加密状态和事务兼容性，不能卸载仍负责未决操作核对的适配器。

## 八、交付、回接与结束条件

交付公开 schema、登记清单、兼容映射和代表性客户端检查。必须明确哪些是只读查询、哪些会创建本地文件、哪些需要具体业务授权，避免工具描述和实际执行行为不一致。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
