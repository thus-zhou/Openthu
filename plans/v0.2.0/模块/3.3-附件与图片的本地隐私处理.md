# 3.3 附件与图片的本地隐私处理

版本目标：Openthu v0.2.0｜批次：3｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

为图片模型输入和课程资料引用提供受控的本地素材管道，保证文件被明确选定、类型与大小可验证、元数据受到处理，并且整个过程不会默认把个人文件发送给外部模型。

必须先取得第2批全部模块（2.1、2.2、2.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

新增 src/thu_assistant/media_assets/、受控临时目录与媒体测试；不修改 models.py 或通用下载实现。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 定义素材描述对象，区分用户明确选定文件、已授权下载的课程附件和公开合成测试文件。每项保留逻辑编号、用途、来源、内容类型、大小与哈希；公开描述不带绝对路径，真实路径只在当前进程的受控解析表中保存。

2. 建立文件读取边界，要求普通文件、明确可读权限和允许的类型，拒绝链接越界、目录、设备文件、超限大小及明显伪装内容。检测内容签名与扩展名的一致性，不能仅依赖浏览器或模型给出的 MIME 文本。

3. 对允许的图片执行像素、尺寸和解码资源限制，处理方向后去除定位和设备等不必要元数据。保留原文件不覆盖，产生的派生图放入受控临时区；记录变换后的哈希，避免使用原图哈希误标派生内容。

4. 文件引用只在同一账号、同一任务授权和限定时间内可解析。下载 URL 与本地引用分别处理，不让模型传入任意路径、任意外部地址或认证头；需要读取网页图片时仍走已有下载授权和域名规则。

5. 为发送给学校模型建立独立的素材清单和内容预览，标出将发送的文本、图片数量、目标模型及大小。只有本次请求明确包含这些素材时才交给传输模块，模型能力探测不得自动发送真实图片。

6. 把媒体处理与网络传输分离，当前模块只产出可消费的内存数据或受控引用。图片本身不进普通日志和全局缓存，编码后的内容不能进入异常消息、终端回显或版本交接记录；需持久化的临时状态使用前批加密提供者。

7. 支持取消、超时、处理失败和进程退出后的清理规则。正在使用的引用不能被其他任务误删，未完成清理有明确清单和保留期限；安全清理是关闭句柄和移除临时文件，不宣称对所有存储介质都完成了物理擦除。

8. 提供纯本地合成图片与附件样例，覆盖解码失败、伪装格式、超大尺寸和元数据。给多模态模块提供稳定引用接口，给资料模块提供来源信息接口；公共工具层如何接收新参数由后续集成模块处理。

## 四、数据与接口约定

素材清单至少包含 asset_id、account_scope、purpose、mime、bytes、sha256、expires_at 和转换说明。引用不是永久下载地址，也不自动授予另一次请求使用文件的权限。输入路径与网络 URL 不在同一字段中混用，调用者必须明确素材来源。

## 五、异常、退化与兼容

格式不支持、内容异常、像素超限、引用过期、账号不符和取消分别返回错误。处理失败不得退回无检查原图继续发送，也不得为了成功读取而放宽文件边界。引用失效不等同于原始课程资料已被删除。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 把图片扩展名改为其他类型，处理器仍应基于内容正确拒绝伪装。
- 使用包含合成定位元数据的图，派生输出不得保留该元数据。
- 构造小文件但极大解码尺寸，必须在资源上限内失败。
- 其他账号或过期任务使用已有引用时，解析必须拒绝。
- 取消处理和模拟磁盘空间不足时，不生成可发送的半成品。
- 在整个素材准备过程中拦截网络，确认不会发送任何请求。
- 检索错误、日志和交接描述，确认无图片编码、真实路径或认证信息。
- 完成任务后检查临时目录及句柄，确认派生文件按约定清理。

## 七、回退与恢复

关闭媒体输入即可回到纯文本模型与原文件下载功能；原始文件始终保留不变。清理未使用派生缓存前核对使用计数和任务状态，不能误删使用者下载目录中的原始附件。

## 八、交付、回接与结束条件

交付素材引用协议、类型与资源限制、元数据处理和清理测试。后续多模态实现必须调用此边界，不能另外开一个绕过检查的本地路径或任意图片 URL 参数。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
