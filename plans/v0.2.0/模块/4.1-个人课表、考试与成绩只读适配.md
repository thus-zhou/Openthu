# 4.1 个人课表、考试与成绩只读适配

版本目标：Openthu v0.2.0｜批次：4｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

在已经确认来源契约的前提下补齐个人学业数据读取，把课表、考试与成绩做成独立、可追溯的只读能力，给后续日程汇总提供可靠输入，避免由日历或作业反推完整学业记录。

必须先取得第3批全部模块（3.1、3.2、3.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

新增 src/thu_assistant/academics/ 与学业夹具；不修改 queries.py 注册、todos.py 或 MCP 公共工具。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 先读取来源启动表，逐项确认课表、考试和成绩是否具备足够接口依据。三者分开启用；某项缺少关键契约时只完成模型、错误和隔离入口，标记阻塞，不把其他来源能登录视为该业务可读。

2. 实现统一学期选择和课程关联，优先使用来源学期与课程编号，保留同名课程、重修和不同教学班。没有稳定编号时生成带来源范围的临时标识并明确限制，禁止通过名称相近自动合并课程。

3. 课表解析分别保留教学周、单周双周、星期、节次、日期区间、地点和平台时间。只有已核对当前校历、节次时间表与适用学期，才展开成具体日期；遇到缺校历或临时调课信息时保留原始周期表示及不完整提示。

4. 考试解析保留考试编号、课程关联、日期、开始结束时间、地点和来源状态。只给日期时不补考试时刻；补考、缓考、取消和改期有独立状态。来源未声明覆盖全部考试时，结果不能声称个人所有考试已经读取。

5. 成绩读取区分课程成绩、学分、绩点、等级、通过状态和平台未发布字段。保留数值、文本及未知值，不能把缺成绩当零分，不使用未经核对的公式计算绩点或学业排名，也不把作业分数充当正式课程总评。

6. 对来源分页、筛选和权限执行统一结果规则，每条数据带检查时间与证据类别。个人成绩默认不落未加密缓存，不进入看板公共摘要或模型请求；调用方必须明确请求该类敏感学业信息。

7. 设计只读查询接口和适配能力描述，参数仅含学期、课程和业务范围等登记字段，不允许任意请求头、Cookie 或上游接口路径。传输层复用既有认证与域名规则，新增来源不得扩大为任意内网代理。

8. 建立来源解析和业务映射的合成测试，分别验证周期展开、冲突和未知时间。提供供待办模块消费的考试与课表事件转换器，成绩不自动变成待办；到集成阶段才统一登记公开查询操作。

## 四、数据与接口约定

建议内部操作分为 timetable、exams、grades，实际登记名称由契约冻结和集成记录确认。课表条目保留周次与日期展开依据；考试保留事件状态和精度；成绩保留来源字段与是否已发布。任何推导值都必须带 derivation 标记及所用规则版本。

## 五、异常、退化与兼容

学校页面变成前端壳、字段改版或身份权限不足时，停止该适配并给出来源状态。多来源时间冲突保留双方证据，不擅自选择最新标题。缺失生产契约是发布范围问题，不能通过补造夹具来消除阻塞。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 同名课程跨学期及不同教学班应保持独立记录和正确关联。
- 单周、双周、节假日和跨周课程展开必须遵守显式校历规则。
- 缺节次时间表时保留周期信息，不输出虚构的具体上课时刻。
- 考试仅有日期、取消或改期时，事件模型必须保留精度和状态。
- 未发布成绩、等级成绩和零分分别显示，不能相互转换。
- 来源第二页失败时，已读条目可以返回但完整性必须下降。
- 成绩查询日志、公共看板摘要和模型上下文不得自动包含成绩原值。
- 未取得契约的子能力调用时应返回明确未支持，不能返回模拟成绩。

## 七、回退与恢复

按来源分别停用新学业操作，保留原网络学堂课程与教务日历读取。删除派生缓存前保留来源和规则版本，不能因新适配失败清空既有个人数据；对旧事件游标明确使其失效并重建。

## 八、交付、回接与结束条件

交付三类只读适配、来源映射、周期和精度测试以及启用状态表。已有依据的子能力必须完成实现；缺依据的子能力留下明确缺口与接手请求，禁止在版本摘要中笼统写成完整教务系统已接通。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
