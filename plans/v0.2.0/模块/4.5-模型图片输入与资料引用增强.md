# 4.5 模型图片输入与资料引用增强

版本目标：Openthu v0.2.0｜批次：4｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

保留现有文本对话和引用映射，增加有明确来源依据的图片输入及更可靠的资料上下文，控制敏感素材发送范围、模型能力判断、用量表达和取消后的结果处理。

必须先取得第3批全部模块（3.1、3.2、3.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

models.py、models.js 与模型传输专用模块；gateway.js 的分派注册由 6.1 负责，媒体解码由 3.3 提供。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 核对当前目录解析、模型选择和上游代理传输路径，把官方标注、请求协议已核对和实际生成可用分别表示。目录显示支持图片不能直接启用传输，只有前批证据足够的模型和请求格式才进入可用清单。

2. 设计向后兼容的输入模型，旧 prompt 和 messages 保持既有二选一语义。图片仅通过受控素材引用或已经验证的媒体对象传入，不接受任意本地路径、认证头或未经审查的外部 URL；旧文本调用不因新增图片参数而改变结果类型。

3. 接入媒体管道的明确选择清单，核对账号、用途、有效期、格式、张数及总字节限制。发送前形成文本和图片范围摘要，实际请求只携带本次选择内容，不自动读取相邻文件、整门课程资料或历史成绩。

4. 按已验证的上游契约构造多模态消息，保持文本顺序与图片顺序，拒绝重复或失效引用。学校代理不能承载某种媒体格式时明确失败，不试探性地转为其他未经核对协议，也不把整份文件编码后塞进普通文本提示词。

5. 增强来源映射，区分原文引用、派生图片、文本摘要和用户输入。输出保留来源标识与内容哈希，但引用匹配只证明标识存在，不证明模型结论正确；文件处理或图片清洗产生新哈希时必须保持转换链可追溯。

6. 统一多模态请求的长度、输出限制和用量处理，目录中的限制不明确时采用保守可配置上限。上游缺用量仍显示未知，不能根据图片数量伪造消耗；回答被截断、拒绝、断流和取消分别保留已取得的部分结果。

7. 取消必须传播到传输与媒体引用生命周期，已开始响应的请求不自动重发。只有已有契约允许的未开始响应认证恢复才可重试一次；取消不承诺学校后端未计费，也不能自动换模型把同一组个人图片再发送一次。

8. 用合成图片、假模型目录和假传输验证请求形状，记录文本兼容性与敏感输出清洗。给集成模块提交参数扩展和能力描述，正式工具仍沿用 model_chat 与 list_models，不为每种媒体新增重复 MCP 工具。

## 四、数据与接口约定

模型能力对象保留媒体类型、输入限制、目录时间、协议依据与可用状态。媒体引用对象来自 3.3，来源映射与输出引用字段保持兼容。图片模型调用可以返回不支持或需要配置，不能以模拟回答填充真实生成结果。

## 五、异常、退化与兼容

模型未知、媒体不受支持、引用过期、内容过大、额度不足及传输中断分别报告。异常不附图片编码、提示全文和认证信息；出现协议不匹配时禁用对应能力，不悄悄降级为一次丢失图片的文本请求。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 原有单轮和多轮文本请求应保持参数与返回兼容。
- 目录支持图片但缺传输依据时，调用必须拒绝而不是猜请求体。
- 传入其他账号、过期或超限素材时，假远端请求计数应为零。
- 发送范围只能包含明确选择的文本和图片，不能读取同目录其他文件。
- 未知引用标识应被提示，已知标识也不能被写成事实已经核验。
- 响应开始后取消或断流，再次查询状态不能触发第二次生成。
- 用量缺失和部分输出分别保留未知与未完成状态。
- 日志、错误、进度和公开交接不得包含图像编码或提示词全文。

## 七、回退与恢复

独立关闭图片输入，保留文本目录和对话能力。清理未使用的媒体引用，但不删除使用者原文件；有结果不确定的模型请求保留必要状态，不在回退时自动重新生成。

## 八、交付、回接与结束条件

交付文本兼容测试、媒体参数、协议驱动传输和来源映射。未取得图片协议依据时必须在能力表中明确阻塞，不因完成了素材清洗模块就宣传多模态已全面接通。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
