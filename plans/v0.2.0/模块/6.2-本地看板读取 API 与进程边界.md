# 6.2 本地看板读取 API 与进程边界

版本目标：Openthu v0.2.0｜批次：6｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

为轻量本地看板提供有边界的读取服务，集中访问课程、待办、资料和已有预约，保持身份状态在后台受保护，防止把本地界面变成可被外部网站调用的校园代理。

必须先取得第5批全部模块（5.1、5.2、5.3、5.4）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

新增 src/thu_assistant/local_api/ 与 API 安全测试；只消费业务门面契约，不修改 MCP 分派、业务适配或前端静态文件。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 先按冻结契约实现 API 路由和响应，不等待同批门面代码的内部细节。开发时注入门面夹具，批次回接后替换为真实实现；禁止为了联调临时修改另一模块的参数或在路由里直接抓取学校页面。

2. 默认仅监听回环地址和随机或明确指定端口，拒绝默认绑定所有网卡。检查 Host 与来源，关闭不必要的跨域访问，防范重绑定和外部网页访问；路径、方法和请求体大小实行白名单，不暴露任意 HTTP 转发功能。

3. 首次启动通过受保护的本机通道建立会话，访问凭证不放在 URL、启动日志和公共配置里。会话 Cookie 采用适合本地同源运行的保护属性，并限制有效期；非读取操作即使只是刷新缓存也应检查来源及防伪请求凭据。

4. 本版本看板采用只读业务范围，展示课程、日程、资源、预约摘要与健康状态。预约执行、作业上传、付款、密钥管理和自动模型生成不提供可触发路由；需要办理时只引导到现有受控入口和明确的下一步说明。

5. 为列表和详情增加有界分页、超时、取消及错误隔离，多个页面组件复用同一账号门面和调度器。前端刷新频率有最小间隔，默认用户主动刷新，不启用持续校园轮询；某个来源失败不能拖住其他卡片和关闭程序的操作。

6. 输出面向显示的字段投影，去除 Cookie、票据、成员原值、私人文件路径和内部异常。链接只允许已核对的安全来源，不能把学校认证跳转地址原样交给浏览器；资源下载通过受控引用与显式动作处理，不提供目录遍历接口。

7. 明确服务启动、关闭和子进程所有权，退出时取消本实例持有请求并释放资源，不能结束使用者日常浏览器或其他助手进程。持久信息按账号加密，临时会话与进程实例绑定，重启后不沿用失效前端令牌。

8. 用协议夹具和本地自动化客户端验证路由、鉴权与关闭行为，给前端模块提供固定样例和接口说明。若需新增 Web 运行依赖，提交许可证与打包清单给 6.3，不在同批直接修改公共元数据文件。

## 四、数据与接口约定

本地读取 API 使用固定版本前缀，返回请求编号、来源完整性及可显示结果。路由清单和状态码由第一批冻结；客户端传入的服务名与资源编号只映射登记操作，不能成为后台任意文件或网络地址。

## 五、异常、退化与兼容

未经认证、错误来源、未知 Host、过大请求、速率超限和服务不可用分别返回安全结果。前端会话失效时只要求重新建立本地连接，不能因此反复登录学校或触发账号凭据重置。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 从外部来源携带读取或写请求，应被来源和会话检查拒绝。
- 使用伪造 Host、跨站页面和缺失防伪凭据，不能改变本地状态。
- 遍历路径、任意 URL 与未知路由不能访问私人文件或代理学校请求。
- 缺少校园认证时，可返回清楚的未登录卡片，不能泄露后台状态。
- 一个来源超时后，其他独立卡片和服务关闭仍应正常。
- 检查所有响应和启动日志，确认无令牌、票据及私人路径。
- 多实例并存时关闭其中一个，不能杀死另一个网关或浏览器。
- 扫描路由目录，确认不存在真实预约、提交、付款及自动模型生成入口。

## 七、回退与恢复

停止本地服务并关闭相关入口，不影响原 MCP 和 CLI。只清理本实例临时会话，不删除学校会话或未决事务；恢复前验证监听范围与鉴权配置，禁止以关闭鉴权来解决访问故障。

## 八、交付、回接与结束条件

交付读取 API、身份边界、资源关闭流程与安全样例。前端执行者必须能用纯合成数据独立开发，服务在无校园账户条件下应可启动并准确显示能力缺口。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
