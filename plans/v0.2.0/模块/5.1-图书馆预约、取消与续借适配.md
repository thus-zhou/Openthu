# 5.1 图书馆预约、取消与续借适配

版本目标：Openthu v0.2.0｜批次：5｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

完善现有座位和研讨间办理，并在契约成立时增加借阅续借，统一使用已冻结的授权和结果核对机制，使每种动作都有明确输入、预检、派发和未知结果恢复路径。

必须先取得第4批全部模块（4.1、4.2、4.3、4.4、4.5）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

library_actions.py、library_wire.py、library_contracts.py 及新增 renewal 模块和对应测试；不修改公共事务框架及只读解析器。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 逐项接回图书馆读侧预检对象和统一事务契约，核对现有座位、研讨间及取消操作与新存储和授权结构的兼容。旧操作名保留，新增字段先作为可选项；真实平台规则全部来自已登记来源，不能把测试默认值用于生产。

2. 座位预约绑定区域、座位、日期、平台完整时段及地图控件，预检重新核对可用状态和显示标识。地图变化、同名座位或时段调整时重新准备，不通过位置顺序猜座位，也不把页面首页余量当成该座位可约。

3. 研讨间预约逐一核对房间、时间、人数、真实成员和主题，区分成员已识别、成员待确认及审批要求。身份遮掩或多人匹配时返回官方处理需求，不能从群聊、旧记录或相似姓名补造成员编号。

4. 取消分别绑定座位或研讨间的本人记录，核对当前状态、申请人、资源、时段和规则。记录从列表消失不能单独证明取消成功；只有受理证据与充分记录核对相互支持时，才更新最终取消结论。

5. 续借仅在来源契约明确后启用，绑定借阅记录、单册标识、当前到期时间和平台限制。准备阶段只读取资格，不发续借请求；执行后重新查询本人借阅，核对是否同一记录及新的到期结果，不能把“允许续借”或接口二百状态当成已续借。

6. 每个写操作按照精确请求序列派发，并在派发前保存加密状态。响应丢失、审批中、成员同意中和记录延迟分别保留状态，重复执行只核对；需要校方页面处理时给出受控官方入口，不绕过学校验证。

7. 将办理后的可核对结果与待办刷新参数关联，更新的是对应来源和时间窗口，不能直接在本地伪造一条成功预约。记录原值只留在受保护日志，公共结果对成员、主题和敏感记录标识按既有规则脱敏。

8. 补齐三类办理及续借的契约测试、并发和故障注入。生产请求仅在实际有可靠契约且获得具体授权时可进入派发；本模块的验收通过自动化夹具完成，不创建预约或续借来填充成功证据。

## 四、数据与接口约定

保留现有三项图书馆操作，新续借建议登记为独立 renew_loan，最终名称由 6.1 固定。四类动作均返回计划或事务引用，结果核对必须同时比较账号域、源记录、关键业务字段与平台状态；审批中不升级为成功。

## 五、异常、退化与兼容

资格不足、规则变化、成员歧义、记录不唯一、续借没有新结果和取消证据不足分别处理。平台不支持撤销续借时明确不可回滚，不能为了统一回滚界面虚构反向操作或擅自取消其他预约。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 座位地图编号变化后执行旧计划，必须拒绝且不派发。
- 研讨间人数不足、成员遮掩或成员列表变化，应进入重新准备或官方处理。
- 非本人记录和不匹配系统的取消请求必须被拒绝。
- 取消列表为空但缺少受理证据时，结果保持未知。
- 续借资格通过但执行响应失败，原到期时间不能被本地改写。
- 续借响应丢失后重复执行，只允许查询新到期结果。
- 审批延迟和记录迟到应保持可继续核对的状态。
- 停用图书馆写操作后，查询和历史未决事务仍可恢复。

## 七、回退与恢复

按操作关闭新派发，保留已有适配器版本供日志核对。代码回退不撤销真实预约和续借，不删除成员加密数据前先核对未决记录的保留需求；无法读取新状态时保留独立恢复工具。

## 八、交付、回接与结束条件

交付操作契约、四类状态映射及失败恢复证据。预约、取消和续借的实现状态分别登记，缺续借来源时不能把本模块整体描述为已支持续借，范围变动须进入版本问题清单。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
