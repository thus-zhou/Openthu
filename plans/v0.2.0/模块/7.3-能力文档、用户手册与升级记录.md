# 7.3 能力文档、用户手册与升级记录

版本目标：Openthu v0.2.0｜批次：7｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

统一产品说明、安装使用、隐私边界、能力等级和版本升级资料，使新用户、Hermes、Codex 与其他贡献者能基于同一份实际状态工作，消除旧阶段说明与现有实现之间的矛盾。

必须先取得第6批全部模块（6.1、6.2、6.3）验收并回接的集成提交。本批同批模块可并行，仍须遵守独占路径及冻结接口；前后批不得重叠开工。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

README.md、docs、CHANGELOG.md、集成技能说明与贡献维护文档；不修改计划原始字数段、代码入口和测试断言。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 逐项对照当前注册操作、各模块交付和来源证据，建立功能事实表。旧文档中仍描述生产适配器为空、Linux 完全不可用或作业只有准备等内容需要按最终实现修订，但原始历史记录保留时间与语境，不能简单改写历史通过结论。

2. 把能力分为代码已实现、环境已就绪、协议有依据和真实业务有证据几个维度。生产适配未启用、需要官方验证、缺认证或尚待来源核对分别写明；不能把模拟测试通过升级成真实办理完成，也不能用一个总表的“支持”隐藏关键限制。

3. 重写首次使用路径，按完整安装、配置诊断、建立本人认证、只读查询、查看看板和明确授权办理的顺序说明。Windows 与无桌面 Linux 的密钥和交互条件分别描述，不要求读者复制维护者目录、Cookie 或设备信息。

4. 补充课程资料中心、日程筛选、增量变化、日历导出和图片输入的使用说明，给出合成参数及预期状态。所有示例来自公开入口与合成资料，不展示用户真实课程清单、成绩、主机地址、文件路径或图片。

5. 编写升级和回退说明，明确程序包、配置、密钥、会话、下载与未决事务的关系。升级不会自动搬迁个人凭据，也不自动撤销远端业务；状态格式不兼容时说明保留恢复运行时的方法和重新建立会话的条件。

6. 整理二十九个 MCP 工具与新登记操作的对照，保留旧别名及兼容说明。页面、CLI 帮助、技能说明和能力矩阵中的操作名称必须一致；开发者文档说明共享文件负责制、批次屏障及单一版本 PR 的接力方式。

7. 更新变更记录和候选发行说明，按用户可见变化、兼容性、安装资源、已知限制和未完成事项组织。候选状态不写已正式发布，不提前贴成功的真实交易记录；新增依赖的许可证与来源说明由实际清单核对。

8. 校验全部内部链接、命令和示例字段，使用文档中的命令在合成或空状态环境检查可执行性。必要的输出说明只写状态和范围；本方案不增加现场展示、录屏或真实下单作为文档交付条件。

## 四、数据与接口约定

能力事实表以登记操作为主键，关联实现、启用条件、证据、测试和限制。用户手册引用稳定文档或版本链接，不引用本机绝对目录；候选发行说明须与同一提交的实际包和工具目录对应。

## 五、异常、退化与兼容

事实冲突、链接失效、示例参数不合法及能力夸大必须在交付前修正。某功能仍有外部阻塞时保留清楚说明和版本决策，不能用模糊宣传文字消除技术缺口。公开文档不得附原始个人响应。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 能力矩阵中的每个已支持操作都能定位到注册与实现。
- 旧用户按兼容说明调用原命令时，不应遇到文档承诺之外的破坏。
- 新安装步骤不包含个人目录、密码、Cookie 或特定服务器配置。
- Linux 密钥和交互条件与实际提供者一致，不能宣传无条件全自动登录。
- 图片与资料示例不能隐式发送未选择内容或指向真实个人文件。
- 所有内部链接及示例字段通过检查，候选说明无提前发布用语。
- 未知、部分读取、待付款和待审批的文字不应误导为业务成功。
- 回退说明应保留未决事务与密钥，不能建议直接删除整个状态目录。

## 七、回退与恢复

文档回退保留修订记录和对应版本，不能让旧说明覆盖当前真实限制。若代码能力撤回，需要同步撤回入口说明及宣传；已经公开的版本资料用补充说明澄清，不伪造历史状态。

## 八、交付、回接与结束条件

交付完整手册、能力矩阵、升级说明、贡献维护资料和候选发布说明。内容以当前代码与证据为准；“所有学校服务已接通”与“所有人可下载软件”必须分别准确表达。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
