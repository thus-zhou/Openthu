# 8.1 全版本集成、候选构建与交审

版本目标：Openthu v0.2.0｜批次：8｜状态：待实施方案

【执行方案本体】

## 一、目标与开工条件

将所有批次成果形成一个可安装、可恢复、可审查的完整候选版本，消除并行开发产生的接口和资源问题，并把完整证据一次性交给 Codex，而不是再把每个小模块单独交付。

必须先取得第7批全部模块（7.1、7.2、7.3）验收并回接的集成提交。本批为单模块串行关口，不与前后批重叠执行。

先读取总控、本模块和第一批冻结结果，核对实际提交与上批验收，不从聊天里的旧完成汇报推断当前状态。工作区有未提交内容时先辨明负责者和来源，保留改动，不执行强制重置、清空目录或覆盖式拉取。发现基线不同先登记差异，解决后再实施，不能边写边猜依赖版本。

## 二、修改范围与并行纪律

版本集成分支、集成清单、必要的回接修复、候选资产及总体验收记录；本批只有本模块，暂停其他开发者对集成分支写入。

本模块对列明路径负责，新增目录也要登记。你并非仓库中的唯一执行者，不撤销他人提交；同批只读公共契约，在独立辅助分支开发，不同时向集成分支推送。同批缺少的实际组件可以用冻结协议的显式夹具开发，夹具不得进入生产默认路径；回接后再核对真实接线。需要修改他人文件时先登记交叉请求，由集成人处理，不能扩大自己的修改范围。

## 三、实施顺序

按下列步骤小步推进，每一步先确定输入、输出与可能副作用，再实现最小可核对改动。保留原有兼容测试，新增用例围绕行为、故障和边界，不写只复制实现细节的空断言。发现失败先定位归属并保留复现；只暂停受影响路径，独立且已授权的工作可继续。修复后重跑受影响检查，不重复运行已经通过且未被新改动影响的整套测试。

1. 确认前七批状态、精确提交和交付清单，按模块顺序将辅助分支回接唯一集成分支。出现冲突先比较契约与负责边界，保留已有贡献和测试，不使用整文件覆盖解决冲突；回接完成后冻结候选代码，暂停并行改动。

2. 逐项核对公共数据、存储、媒体、业务门面和本地 API 的实现与冻结契约。重点检查同批针对夹具开发的组件在实际接线后是否一致，删除仅供联调的临时旁路，确保所有正式调用仍经过相同授权与隐私边界。

3. 处理包资源和前端最终资产，核对源码、wheel、sdist 和完整归档的清单。统一产品版本为候选的零点二版本，状态格式版本另行保留；命令帮助、工具目录、技能说明和文档都应指向同一候选行为。

4. 执行版本级 Windows 与 Linux 检查，在临时状态和合成校园传输下覆盖查询、资料、日程、看板、图片和办理恢复。无需真实账号、付款或下单即可验证工程行为；自动化 UI 只使用合成服务，不把现场展示列为通过标准。

5. 在全新目录恢复候选安装并从仓库外运行，验证程序没有借用源码路径、旧 node_modules 或旧用户配置。分别检查缺资源、无密钥和来源未启用的表现，确认失败提示与能力矩阵一致，不依赖开发环境残留让包勉强可用。

6. 执行源码、Git 历史、构建包、校验文件和说明的隐私核对，检查作者身份、邮箱、绝对路径、主机、认证 URL、个人记录及图片。第三方公开词表中的数字碰撞需按来源和上下文审查，不能为了消除误报破坏上游内容哈希。

7. 逐项关闭版本计划验收项。条件适配缺少依据或承诺功能未完成时，候选保持阻塞，并提供具体问题及可继续工作；只有使用者明确同意范围调整后才能更新计划，禁止执行者自行删掉难项并声称完整升级已经完成。

8. 准备整体变更、测试、兼容性、已知限制、恢复方法及候选资产清单，更新同一个版本 PR。只有全部门槛满足才转为正式交审；交出代码所有权并提供准确提交，Codex 审查期间不继续往同一分支混入未说明的新功能。

## 四、数据与接口约定

交审清单包含目标版本、源码提交、树哈希、各批验收、条件适配结论、平台结果和资产 SHA256。每个报告都绑定候选提交；修复产生新提交时标记受影响证据失效，并重新运行必要检查，不复用旧资产冒充新候选。

## 五、异常、退化与兼容

接口不匹配、资源缺失、隐私发现、测试失败和能力声明不实均阻止交审。缺外部契约要保留明确阻塞，不伪造网络成功。没有用户范围决策时宁可保持候选状态，不能静默裁剪版本目标。

## 六、必须覆盖的验收用例

用例都使用合成账号、事件、文件和假校园传输；默认拦截外发请求，记录读取与写入次数。本地真实浏览器仅访问合成页面，工程验证不需要真实占座、付款或交作业。测试编码器与生产密钥后端必须可辨别，不能以开启假加密换取通过。跳过检查写明平台原因，未执行、模拟通过和真实业务证据分别记录。

- 同批独立组件真实接线后，字段、分页和错误语义应与契约一致。
- 完整包从新目录安装后，可运行代表性合成查询和本地看板。
- 生产密钥缺失时只能影响相关能力，不得启用假加密获得通过。
- 旧客户端和原命令仍保持约定的参数与主要返回兼容。
- 候选归档成员与允许清单一致，无源码外私人文件和运行目录。
- 相同提交的资产及校验清单互相对应，不混用旧包。
- 条件模块未完成时，计划和候选说明必须明确阻塞或获准调整。
- 版本 PR 包含完整总结与接手位置，小模块提交不能被当成版本完成。

## 七、回退与恢复

候选未发布时可回到前一集成检查点，但保留所有模块提交和问题证据。已写入本地新格式状态要保留兼容恢复工具；集成失败不删除用户配置，也不自动撤销任何远端业务。

## 八、交付、回接与结束条件

交付一个完整版本候选、唯一版本 PR、经过核验的构建资产和总体验收记录。此阶段不创建正式发行，不推送代表已发布的版本标签，完成标志是 Codex 收到能够独立复核的完整交付。

交付安全的模块结果说明与机器可读摘要，包含模块编号、基线、最终提交、负责路径、执行检查、结果和剩余阻塞。原始异常、认证响应、主机信息和用户目录不提交；公开摘要只保留错误类别及合成复现。提交前检查差异与隐私，模块代码及时提交推送，进度更新到原版本计划，不为本模块新建交付 PR。

单模块通过不等于批次通过。集成人按顺序回接同批成果，核对无冲突、无遗漏并完成契约联调后，形成唯一批次提交，才允许下一批开工。常规先执行差异检查和本模块必要用例；批次回接再运行开发检查与全量离线回归，命令沿用 python scripts/dev.py check 和 python scripts/dev.py test。若命令因本批修改变化，先核对兼容说明，不自行换成不覆盖相同行为的简化检查。

遇到缺来源、缺授权或不可恢复冲突时保留明确阻塞，禁止用伪造接口、真实个人数据或弱化保护消除问题。会话到达运行限制前保存已完成步骤、提交、下一条动作和待核对事项；恢复会话后沿用原模块与版本分支。需要 Codex 接手时交出具体范围，整套版本仍由原总任务跟踪。
