## 关键设计

- 三条独立证据轴：目录标称（`catalog_support_image`）、协议核对（`protocol_state`）、
  能力结论（`capability_state`）。目录标称为真且无协议证据时只能是 `UNVERIFIED`，
  只有 `SYNTHETIC_TRANSPORT`/`LIVE_READ` 证据的协议档案才可得到 `AVAILABLE`。
- 出厂构建的 `ProtocolRegistry` 为空：所有图片调用在解析引用、读取字节或发出请求之前以
  `MODEL_IMAGE_PROTOCOL_UNVERIFIED` 失败。这是设计结果，不是遗漏；图片能力在能力表中
  明确标为阻塞，不因 3.3 完成素材清洗就宣称多模态已接通。
- 输入只接受 `images: [{media_id}]`；路径、URL、认证头、原始字节、额外字段一律拒绝。
  账号、任务授权、暂存根目录由宿主通过 `MediaBinding` 绑定，不进入工具 schema，
  模型无法选择其他账号或目录。
- 发送必经 3.3 的 `manifest → prepare_model_bundle → authorize_model_send →
  consume_model_bundle`；消费后重新核对每个 `OutboundImage` 的 media_id、MIME、
  字节数与 sha256，再写入 0600 的私有暂存文件。
- 暂存而非内联：网关 stdin 单帧上限 2 MiB，8 MiB 图片内联会被截断。Node 传输按
  `[a-f0-9]{32}.bin` 精确文件名、精确字节数、sha256 校验读取，读完立即删除；
  Python 在 `finally` 再删一次，崩溃遗留由下次请求按 900 秒扫除。
- 来源映射区分四类：`ORIGINAL_QUOTE`（调用方文本）、`DERIVED_IMAGE`（重编码图片，
  含 `source_sha256 → sha256` 转换链）、`USER_INPUT`（输入摘要，只留字符数与哈希）、
  `TEXT_SUMMARY`（模型输出）。引用匹配只证明标识已登记，`claim_verified` 恒为 false。

## 安全属性

- 图片只能来自 3.3 登记过、`purpose=MODEL_INPUT`、`external_transfer_allowed=True`、
  未过期、同账号同任务的引用；其他账号、过期、重复、超限、错误 MIME 在假传输上的
  请求计数为 0。
- 协议档案不能放宽 1.1 冻结上限（单图 8 MiB、每次 4 图、合计 16 MiB、1600 万像素），
  只能取更小值；构造函数直接拒绝更大的值。
- 传输前只暂存被点名的图片，同目录其他文件不会被打开；测试用同目录邻居文件与
  `source_reads` 计数验证。
- 取消（`CANCELLED`）传播到媒体生命周期：撤销该任务授权，暂存文件删除，已开始响应
  不重发；未开始响应的 401 认证恢复最多一次，同一模型、同一图片集合，证据记录
  `image_input.sends=2`，`automatic_replay=false`。
- 错误与证据只含计数、标识与哈希，不含图片编码、提示词全文、暂存路径或认证信息；
  错误码优先沿用 3.3 的 `MEDIA_*` 冻结分类，其余为 4.5 模块码（见跨模块请求）。
- 用量只来自上游：缺失时 `usage=null`、`usage_state=UNKNOWN`，不按图片数量推算；
  截断、拒绝、断流、取消分别保留已取得的部分文本与 `image_input.complete=false`。

## 剩余阻塞

- **生产模型图片传输没有协议依据（OPEN）**。官方目录只提供 `supportImage` 标称，现有
  代理的请求结构、支持模型、字节/像素/张数限制与错误语义均未核对；按
  `docs/contracts/model-image.md`，在取得官方文档或经使用者授权的合成探测证据前，
  不实现生产图片传输。影响：图片调用以 `MODEL_IMAGE_PROTOCOL_UNVERIFIED` 失败；
  文本对话、`list_models` 与既有工具不受影响。解除方式：形成一条
  `ProtocolProfile`（协议 id、模型、消息形状、媒体类型、限制、证据级别），由 6.1 从
  配置注入；本模块不内置任何档案，也不提供“猜测即开启”的开关。

## 剩余边界

- 生产代码默认空协议注册表；因此“4.5 完成”指门控、预览、发送、来源映射与拒绝路径完成，
  不等于多模态已对真实学校代理可用。
- 传输暂存会在 3.3 之外再落一份已清洗图片，0600 文件、0700 目录、读后即删；崩溃遗留最多
  保留 900 秒。没有物理擦除或安全内存擦除承诺。
- 网关 stdin 单帧上限 2 MiB，是选择暂存而非内联的原因；若 6.1 改变分帧协议，需要同步
  复核该上限。
- 图片只能附加在最后一条 user 消息之后；多轮历史中的 assistant 消息按原样保留，不做
  图片回溯插入。
- 协议证据按模型精确匹配，不做通配；同一模型的不同代理路径需要各自档案。
- 能力结论使用 3.3 的 `model-image-capability-v1` 冻结对象，媒体类型与限制放在协议描述
  （`preview.protocol`）中，因为该 schema 不允许额外字段。
- Windows 没有 POSIX 模式位：暂存目录私有性依赖用户目录 ACL，本模块只拒绝相对路径、
  符号链接与非目录。
