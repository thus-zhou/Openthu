## 关键设计

- 三条独立证据轴：目录标称（`catalog_support_image`）、协议核对（`protocol_state`）、
  能力结论（`capability_state`）。目录标称为真且无协议证据时只能是 `UNVERIFIED`，
  只有 `SYNTHETIC_TRANSPORT`/`LIVE_READ` 证据的协议档案才可得到 `AVAILABLE`。
- 协议档案没有乐观默认值：`evidence_level`、`source_id`、`synthetic`、`checked_at` 都是
  必填；限制默认是保守的 1 图 / 1 MiB / 合计 4 MiB / 400 万像素，要用满冻结上限必须显式
  声明。省略证据字段是构造错误，不是隐式声明。
- 出厂构建的 `ProtocolRegistry` 为空：注入媒体绑定后的公共 Python 路径在解析引用、读取
  字节或发出请求之前以 `MODEL_IMAGE_PROTOCOL_UNVERIFIED` 失败；当前 MCP 入口尚未注入
  `MediaBinding`，因此返回 `MODEL_IMAGE_INPUT_UNAVAILABLE`。两者都是零读取、零发送，
  能力表明确标为阻塞，不因 3.3 完成素材清洗就宣称多模态已接通。
- 输入只接受 `images: [{media_id}]`；裸字符串、路径、URL、认证头、原始字节、额外字段
  一律拒绝。账号、任务授权、暂存根目录由宿主通过 `MediaBinding` 绑定，不进入工具 schema。
- 发送必经 3.3 的 `manifest → prepare_model_bundle → authorize_model_send →
  consume_model_bundle`；消费后重新核对每个 `OutboundImage` 的 media_id、MIME、
  字节数与 sha256，再写入 0600 的私有暂存文件。
- 预览不创建 broker bundle：用户只看不发时，3.3 的 `_bundles` 不会累积；发送时创建并在
  同一次调用内消费。
- 暂存而非内联：网关 stdin 单帧上限 2 MiB，8 MiB 图片内联会被截断。Node 传输按
  `[a-f0-9]{32}.bin` 精确文件名、精确字节数、sha256 校验读取，读完立即删除；Python 在
  `finally` 再删一次，崩溃遗留由**下一次图片请求**打开暂存区时按 900 秒阈值扫除，没有
  后台定时器。
- 来源映射区分四类：`ORIGINAL_QUOTE`、`DERIVED_IMAGE`（含 `source_sha256 → sha256`
  转换链）、`USER_INPUT`（只留字符数与哈希）、`TEXT_SUMMARY`。引用匹配只证明标识已登记，
  `claim_verified` 恒为 false。

## 安全属性

- 图片只能来自 3.3 登记过、`purpose=MODEL_INPUT`、`external_transfer_allowed=True`、
  未过期、同账号同任务的引用；其他账号、过期、重复、超限、错误 MIME 在假传输上的
  请求计数为 0。
- 协议档案不能放宽 1.1 冻结上限；Python 侧上限直接取自 `MediaLimits`，Node 侧另有
  4 / 8 MiB / 16 MiB 的硬上限，两侧各有一条测试。
- 传输前只暂存被点名的图片，同目录其他文件不会被打开；测试用邻居文件与 `source_reads`
  计数验证。
- 取消（`CANCELLED`）传播到媒体生命周期：撤销该任务授权，暂存文件删除，已开始响应
  不重发；未开始响应的 401 认证恢复最多一次，同一模型、同一图片集合，证据记录
  `image_input.sends=2`、`automatic_replay=false`，Python 证据会保留 `sends`。
- 错误与证据只含计数、标识与哈希，不含图片编码、提示词全文、暂存路径或认证信息；
  错误码优先沿用 3.3 的 `MEDIA_*` 冻结分类。
- 用量只来自上游：缺失时 `usage=null`、`usage_state=UNKNOWN`，不按图片数量推算；
  截断、拒绝、断流、取消分别保留已取得的部分文本与 `image_input.complete=false`；
  成功但被截断的响应不再被写成完整。
- `preview()` 给出完整 `text_scope`（消息数、字符数、角色计数、`source_refs` 标识、
  每条字符数），不再只报告最后一句；预览本身不含提示词正文、图片编码或路径。

  `MODULE_CODES` 与一致性测试锁定了完整清单。

## 剩余边界

- 生产代码默认空协议注册表；因此“4.5 完成”指门控、预览、发送、来源映射与拒绝路径完成，
  不等于多模态已对真实学校代理可用。
- 传输暂存会在 3.3 之外再落一份已清洗图片，0600 文件、0700 目录、读后即删；崩溃遗留
  由下一次图片请求按 900 秒阈值扫除，没有后台定时器，也没有物理擦除承诺。
- 网关 stdin 单帧上限 2 MiB，是选择暂存而非内联的原因；若 6.1 改变分帧协议，需要同步
  复核该上限。
- 图片只能附加在最后一条 user 消息之后；多轮历史中的 assistant 消息按原样保留，不做
  图片回溯插入。
- 协议证据按模型精确匹配，不做通配；同一模型的不同代理路径需要各自档案。
- 能力结论使用 3.3 的 `model-image-capability-v1` 冻结对象，媒体类型与限制放在协议描述
  （`preview.protocol`）中，因为该 schema 不允许额外字段。
- Windows 没有 POSIX 模式位：暂存目录私有性依赖用户目录 ACL，本模块只拒绝相对路径、
  符号链接与非目录。
- 预览只提供范围（消息数、字符数、角色、来源标识），不提供消息正文；需要展示正文的
  确认界面由 6.1 在调用方侧生成，本模块不把提示词复制进证据。

## 回退与下一步

回退只需让 6.1 不注入 `MediaBinding`/`ProtocolRegistry`：图片参数得到
`MODEL_IMAGE_INPUT_UNAVAILABLE`，文本路径、模型目录和 29 个工具入口完全不变；
`THU_MODEL_READ=0` 仍回到旧版单 prompt 行为。回退不重发任何已发出或不确定的模型请求，
也不删除使用者原文件。下一步由集成人把 4.1–4.5 回接到同一批次提交，运行批次级
`check`、全量离线回归与契约联调，并处理 P2-3/P2-13 的跨模块登记。
