## 交付范围

- `src/thu_assistant/events.py`：统一日程项，把原 `get_todos` 行与 4.1 的 `calendar-event-v1`
  统一为 `agenda-events-v1`。事件编号由账号域、服务域、种类、稳定记录号和 occurrence 组成；
  标题和数组顺序不参与。日期级时间保持 `time.kind=DATE`，精确时间保持 `DATE_TIME`；
  `time_semantics` 区分 `DEADLINE`、`INTERVAL`、`OCCURRENCE`；没有日期的项保留为
  `calendar_valid=false`，不补造午夜。严格校验 `calendar-event-v1`：账号域、服务域、种类、
  记录号、标题、`last_modified`、日期/时刻真实解析、`end >= start`、时区与导出状态全部
  失败关闭，非法项进入 `excluded`，不以 `ValueError` 逃逸。`in_window()` 为学业事件提供与
  legacy 待办一致的窗口/终态过滤。视图使用同一 `as_of`；跨午夜区间按“区间与窗口相交”判断；
  冲突只使用可信起止区间。
- `src/thu_assistant/snapshot_diff.py`：按账号、来源、参数和规范版本绑定的增量快照；
  `ADDED`、`MODIFIED`、`CANCELLED`、`DELETED`、`SOURCE_UNAVAILABLE`、`SOURCE_INCOMPLETE`
  变化类型；只有前后均完整且可比较时消失项才是 `DELETED`；来源断线或少读一页时保留原有
  事件为 `HISTORICAL` 并随基线前移。`status` 使用 envelope 的 `OK`/`EMPTY`/`PARTIAL`，
  基线状态另放 `baseline_state`。不透明游标 `evcN.<随机串>` 绑定账号、范围与规范版本，
  600 秒后失效，且明确为 process-local。每 UID 的 `sequence`/语义摘要使 iCalendar
  `SEQUENCE` 在基线过期、范围变化和无安全密钥的进程内路径下都不回退；没有可用加密后端时
  保留进程内基线，绝不写明文。
- `src/thu_assistant/calendar_export.py`：iCalendar、Markdown 与结构化摘要导出。RFC 5545
  转义、75 字节 UTF-8 安全折叠、`Asia/Shanghai` 时区块；日期级截止导出为
  `DTSTART;VALUE=DATE`，不写午夜；稳定 UID、`SEQUENCE` 与 `STATUS:CANCELLED` 支持重复导入。
  Markdown/JSON 使用脱敏字段和 https 来源链接；URL 的 `|`/括号/反斜杠转义，JSON 字符串
  中和公式前缀。写入先落同目录临时文件，fsync 后通过硬链接或独占创建原子占用目标；
  检查后出现的竞态目标不会被覆盖。来源不完整时导出默认拒绝，`allow_partial` 时文件头写
  `X-OPENTHU-SOURCE-COMPLETE:false`。
- `src/thu_assistant/todos.py`：`get_todos` 增加可选 `semester` 与
  `academics`/`academics.exams`/`academics.timetable` 选择，默认不读取学业来源。新增
  `agenda()`、`changes()`、`export_calendar()`、`export_agenda()`、`describe_agenda()`。
  `agenda()` 自动收集 Snapshot 全部页，超过 50 页才 `AGENDA_RESULT_TRUNCATED`；学业事件
  在进入 agenda/changes 前按请求窗口过滤；`export_calendar()` 是纯本地写，不读取来源、
  不推进基线；`export_agenda()` 是显式“先读后导”路径。学业能力表只读取可用且未被
  `BLOCKED_*` 结论挡住的能力，默认三者均为 `BLOCKED_SOURCE_EVIDENCE`，显式选择返回
  `UNKNOWN` + `ADAPTER_REQUIRED`，不是 `EMPTY`；成绩不是日程来源。`AcademicBridge` 转发
  `semester` 与 `expansions`，并把真实 `pages_read` 带入状态，使 partial 学业读取成为
  `SOURCE_INCOMPLETE` 而不是 `SOURCE_UNAVAILABLE`。
- `contracts/v0.2/error-classification.json`、`src/thu_assistant/source_state.py`：登记
  5.4 的 29 个错误码（事件、快照、游标、导出），分类为 `INPUT`、`CONFLICT`、
  `COMPLETENESS`、`INTERNAL`、`NOT_IMPLEMENTED`，运行期镜像与冻结表逐项一致。
- `src/thu_assistant/mcp_stdio.py`：只更新 `get_todos` 工具描述，说明学业来源是默认阻塞的
  可选路径；未新增 MCP 工具，29 工具清单不变。agenda/export 的公共接线仍属 6.1。

未修改 `queries.py`、`library*.py`、`spaces.py`、`sports*.py`、`browser.py`、`action_store.py`
或各站点适配器；没有真实校园读取、模型请求或消息发送。

## 限制

- 个人课表、考试、成绩生产适配仍是 `BLOCKED_SOURCE_EVIDENCE`；本模块只接通能力表和转换
  边界，没有真实考试/课表/成绩读取。
- 课表事件需要显式展开输入；真实 `AcademicBridge` 已转发 `expansions`，生产 4.1 reader
  仍阻塞。
- 无安全密钥时只有进程内快照/序号，跨进程需重新取快照；游标始终是 process-local。
- iCalendar 的 `STATUS:UNKNOWN` 按 RFC 导出为 `TENTATIVE` 加 `X-OPENTHU-CALENDAR-STATUS:UNKNOWN`，
  不表示成功。
- `THU-TODOS-1` 外层容器和稳定 `record_id` 入 AAD 的迁移仍属后续存储/集成步骤，
  与 4.4 的 `THU-ACTION-1` 边界一致；本模块保持旧缓存可读。
- 待审批、待付款、上传成功和草稿状态不得变成已确认日程（交给 5.1/5.2/5.3 与 6.1 保持）。
