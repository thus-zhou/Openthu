## 交付范围

- `src/thu_assistant/events.py`：统一日程项。由原 `get_todos` 行和 4.1 的
  `calendar-event-v1` 统一成 `agenda-events-v1`。事件编号由账号域、服务域、种类、稳定记录号
  和 occurrence 组成；标题、数组顺序不参与。日期级时间保持 `time.kind=DATE`，精确时间保持
  `DATE_TIME`；`time_semantics` 区分 `DEADLINE`、`INTERVAL`、`OCCURRENCE`。没有日期的项保留为
  `calendar_valid=false` 的无日期项，不补造午夜或日期。状态未知只能是 `UNKNOWN`。保留
  `source_version`、`time_precision`、`timezone`、`source_status`、`checked_at` 与完整性字段。
- `events.py`：严格校验 `calendar-event-v1`。账号域、服务域、种类、记录号、标题、
  `last_modified`、日期/时刻真实解析、`end >= start`、时区、导出状态都失败关闭；非法项进入
  `excluded`，不会以 `ValueError` 逃逸。`in_window()` 为学业事件提供与 legacy 待办一致的
  窗口/终态过滤。
- `events.py`：视图与冲突。提供 `upcoming`、`overdue`、`undated`、`completed`、`by_source`
  视图，全部使用同一个 `as_of`；跨午夜区间按“区间与窗口相交”判断。冲突只使用可信起止区间：
  全天事件、截止时间点、未知时间和缺节次表的周期课程不参与。
- `src/thu_assistant/snapshot_diff.py`：账号、来源、参数和规范版本绑定的增量快照；
  `ADDED`、`MODIFIED`、`CANCELLED`、`DELETED`、`SOURCE_UNAVAILABLE`、`SOURCE_INCOMPLETE`
  变化类型；只有前后均完整且可比较时消失项才是 `DELETED`。来源断线或少读一页时保留原有事件为
  `HISTORICAL` 并随基线前移，不把分页失败变成全量取消。`status` 使用 envelope 的
  `OK`/`EMPTY`/`PARTIAL`，基线状态另放 `baseline_state`。
- `snapshot_diff.py`：不透明游标 `evcN.<随机串>`，绑定账号、范围、规范版本并在 600 秒后失效；
  变更编号确定性生成。游标是 process-local；加密存储只持久化快照和每 UID 序号，不持久化 token。
- `snapshot_diff.py`：每 UID 的 `sequence`/语义摘要存储，使 iCalendar `SEQUENCE` 在基线过期、
  范围变化和无安全密钥的进程内路径下都不回退。没有可用加密后端时保留进程内快照/序号基线，
  绝不写明文。
- `src/thu_assistant/calendar_export.py`：iCalendar、Markdown 与结构化摘要导出。
  RFC 5545 转义、75 字节 UTF-8 安全折叠、`Asia/Shanghai` 时区块；日期级截止导出为
  `DTSTART;VALUE=DATE`，不写午夜；稳定 UID、`SEQUENCE` 和 `STATUS:CANCELLED` 支持重复导入。
  Markdown/JSON 使用脱敏字段和 https 来源链接；URL 的 `|`/括号/反斜杠转义，JSON 字符串中和
  公式前缀。写入先落同目录临时文件，fsync 后通过硬链接或独占创建原子占用目标；失败不留半文件，
  检查后出现的竞态目标不会被覆盖。来源不完整时导出默认拒绝，`allow_partial` 时文件头写
  `X-OPENTHU-SOURCE-COMPLETE:false`。
- `src/thu_assistant/todos.py`：`get_todos` 增加可选 `semester` 与
  `academics`/`academics.exams`/`academics.timetable` 选择；默认不读取学业来源。新增
  `agenda()`、`changes()`、`export_calendar()`、`export_agenda()`、`describe_agenda()`。
  `agenda()` 自动收集 Snapshot 的全部页，超过 50 页才 `AGENDA_RESULT_TRUNCATED`；学业事件在
  进入 agenda/changes 前按请求窗口过滤。`export_calendar()` 是纯本地写，不读取来源、不推进基线；
  `export_agenda()` 是显式“先读后导”路径。
- `todos.py`：学业能力表接入。只有可用且未被 `BLOCKED_*` 结论挡住的能力才会读取；默认三个能力
  均为 `BLOCKED_SOURCE_EVIDENCE`，显式选择返回 `UNKNOWN` + `ADAPTER_REQUIRED`，不是 `EMPTY`。
  成绩不是可选日程来源，也不会进入待办或公开摘要。`AcademicBridge` 转发 `semester` 和
  `expansions`，并把真实 `pages_read` 带入状态，使 partial 学业读取成为
  `SOURCE_INCOMPLETE` 而不是 `SOURCE_UNAVAILABLE`。
- `contracts/v0.2/error-classification.json`、`src/thu_assistant/source_state.py`：登记
  5.4 的 29 个错误码（事件、快照、游标、导出），分类分别为 `INPUT`、`CONFLICT`、
  `COMPLETENESS`、`INTERNAL`、`NOT_IMPLEMENTED`。
- `src/thu_assistant/mcp_stdio.py`：只更新 `get_todos` 工具描述，说明学业来源是默认阻塞的
  可选路径；未新增 MCP 工具，未改变 29 工具清单。因为工具 schema 直接来自 `todos.PROPERTIES`，
  `get_todos` 已暴露 `semester` 与 `academics`/`academics.exams`/`academics.timetable` 枚举；这是
  有意的只读扩展，默认阻塞并返回 `ADAPTER_REQUIRED`。6.1 仍负责 agenda/export 的公共接线。
- `tests/test_events.py`、`tests/test_calendar_export.py`（58 个用例）：覆盖稳定 UID、日期级
  语义、同名跨来源、视图、跨午夜、冲突、学业能力开关、窗口过滤、201 项分页、重复比较、
  断线与缺页、游标、快照/序号内存回退、非法 calendar-event、真实 AcademicBridge 转发、
  导出转义/折叠/时区/UID/序号/取消/不完整来源、范围、公式与脚本注入、TOCTOU 和错误码登记。

未修改 `queries.py`、`library*.py`、`spaces.py`、`sports*.py`、`browser.py`、`action_store.py`

## 限制

- 个人课表、考试、成绩生产适配仍是 `BLOCKED_SOURCE_EVIDENCE`；本模块只接通能力表和转换边界，
  没有真实考试/课表/成绩读取。
- 课表事件需要显式展开输入；真实 `AcademicBridge` 已转发 `expansions`，生产 4.1 reader 仍阻塞。
- 无安全密钥时只有进程内快照/序号，跨进程需重新取快照；游标始终是 process-local。
- iCalendar 的 `STATUS:UNKNOWN` 按 RFC 导出为 `TENTATIVE` 加
  `X-OPENTHU-CALENDAR-STATUS:UNKNOWN`，不表示成功。
- `THU-TODOS-1` 外层容器和稳定 `record_id` 入 AAD 的迁移仍属后续存储/集成步骤，与 4.4 的
  `THU-ACTION-1` 边界一致；本模块保持旧缓存可读。
- 批次 5 已在 `0779fff` 回接并 accepted（回接记录见 `交付/批次门禁记录.md`）；本记录确认 5.4 的交付提交是 `6145ed2`。
