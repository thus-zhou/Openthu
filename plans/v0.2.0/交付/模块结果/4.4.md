### 新增 `consent/`

- `protocol.py`：`host-authorization-v1` 纯函数协议。授权绑定 `plan_id`、`account`、
  业务 `digest`、`adapter_version`、计划创建时生成的 64 位十六进制一次性挑战值、
  `issued_at`/`expires_at`、`source=human` 与宿主事件引用，使用 HMAC-SHA256 签名；
  校验顺序为版本、签名（恒定时间比较）、账号、适配器、计划/摘要/挑战值、来源、引用、
  时间。错误只含类别。
- `store.py`：宿主密钥与待用授权文件使用与事务日志相同的 `protect`/`unprotect`；
  密钥容器 `THU-CONSENT-KEY-1`，授权容器 `THU-CONSENT-1`，POSIX 0600，原子写入并
  回读校验。授权按计划 ID 存放，读取即删除；密钥缺失时失败关闭，不生成替代密钥。
- `cli.py` / `__main__.py`：`python -m thu_assistant.consent --plan <operation_id>`
  本机确认入口，显示计划字段，只有输入大写 `CONFIRM` 才签发；无交互终端返回
  `SPECIFIC_HUMAN_AUTHORIZATION_REQUIRED`，不生成授权。输出不含签名或挑战值。
- `README.md`：授权字段、签发路径、拒绝语义、状态表、请求门禁、副作用清单、
  回退与跨模块接线。

### 修改

- `actions.py`
  - 计划新增一次性 `challenge`、`consent_protocol` 和 `effects`；公开结果新增
    `effects`、`state_history`、`next_actions` 与 `local_confirmation_command`，
    不暴露挑战值、签名或业务原值。
  - 新增 `STATE_ENTRY`/`describe_states()`，明确九个状态的进入条件、授权消费状态
    与远端写入可能；`TRANSITIONS` 保持原语义。
  - 新增 `SideEffectLedger`（`declare`/`sent`/`unknown`，只允许
    `NOT_SENT → SENT → UNKNOWN`，终态拒绝继续修改，最多 50 步）。适配器以
    `accepts_ledger = True` 显式选择，既有 `dispatch(record, gate)` 签名不变。
  - 派发前要求可信证据：有 `consent_verifier` 时先调用它，否则/同时读取本机签发的
    待用授权；没有证据时重新读取计划，若仍为 `PREPARED` 则拒绝，绝不自动同意。
  - 带版本号的授权在引擎内再次验签并核对挑战值；无版本号的进程内确认回调保留为
    兼容路径（现有 Windows 消息框与合成测试），若提供挑战值则必须匹配。
  - 预检比较业务摘要、页面上下文和附件标识列表；任一项变化即
    `PRECONDITIONS_CHANGED_PREPARE_AGAIN`，不发送请求。
  - 认领、失效、核对与中断恢复使用带修订号的条件更新；`DISPATCHING`、授权证据和
    进程号在派发前原子落盘。`NotDispatched` 只有在请求计数为零且副作用清单没有
    `SENT`/`UNKNOWN` 时才归为“确定未发出”。
  - 并发核对冲突改为读取最新记录，不向调用方抛出内部修订冲突。
- `action_store.py`：`update(..., expected_revision=...)` 条件更新；读取时校验
  挑战值、副作用清单与协议字段的类型和范围；旧记录缺少这些字段仍可读。
- `action_recovery.py`：离线盘点增加 `effects`、`pending`、`cancellation=NOT_PERFORMED`
  与 `read_only=true`；仍不访问网络、不调用适配器、不发起取消。
- `browser.py`：通用表单预览增加授权协议与本机确认命令；提交仍返回
  `ADAPTER_REQUIRED`，不打开通用写窗口。

## 安全结果摘要

- 授权只对一笔计划有效；挑战值、签名和宿主事件引用只存在于加密日志与授权文件，
  不进入公开结果、普通日志或 URL。授权文件读取即删除，成功派发后再次执行只查结果。
- 无交互终端、拒绝输入、伪造签名、错误账号/计划/摘要/适配器版本、过期授权均不派发；
  缺失有效证据时计划保持 `PREPARED`，由使用者在本机确认。
- `DISPATCHING` 与授权证据先落盘再发送；落盘失败时远端请求计数为零。
- 认证令牌可在适配器构造请求时刷新；业务摘要、上下文或附件哈希变化必须重新准备。
- 终态、未决和未知状态都不能自动重发；`UNKNOWN` 只提供核对入口。
- 回退盘点只读，输出不含业务原值，`cancellation=NOT_PERFORMED`，删除本地日志不会被
  当作远端取消。
- 未接入真实校园站点；没有新增生产适配器，没有开启真实写入。

## 剩余边界

- 外层 `THU-ACTION-1` 容器与 `operation_id.dpapi` 文件名保持不变；2.2 的新封套已嵌套
  在内，但把稳定 `record_id` 绑定进 AAD 的存储迁移未在本模块完成，留给后续存储/集成
  阶段（3.1 已登记为 4.4/后续事项）。
- 旧的进程内 `consent_verifier` 无版本号授权仍被接受，以保持现有 Windows 消息框和
  合成适配器测试兼容；它同样绑定计划、账号、摘要、适配器、到期时间和 human 引用，
  但没有挑战值和签名。生产上的通用入口使用签名授权；5.2 迁移后旧路径只剩测试使用。
- 并发执行同一计划时，未抢到一次性授权的重复调用会安全失败（不派发）；先到者最多
  发送一次，重复调用应查询结果。这是单次授权的直接结果，不扩大重试。
- `attachments` 字段由具体适配器的业务契约定义；本模块只要求其 `name`/`sha256`/`size`
  标识列表在预览与预检间精确一致，不解释文件内容。
- 本模块没有修改 `docs/contracts/action-boundaries.md`（`docs/` 归 7.3）；授权协议文档
  放在 `src/thu_assistant/consent/README.md`，7.3 汇总时可引用或迁移。
- 真实预约、取消、续借、付款与交作业仍未实现，属于第 5 批；本模块不声称任何真实
  校园写入能力。
