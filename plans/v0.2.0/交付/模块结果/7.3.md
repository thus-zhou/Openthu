### 能力矩阵事实

- 默认 CLI 门面（todos 提供者存在、资料库提供者未注入）下 81 条登记与文档逐条一致：57 条校园只读、3 条学业阻塞、6 条本地/模型、15 条校园写入。
- 可用只读：`info`、`learn`、`library`、`sports` 的登记操作，`campusvisit`/`cloud`/`student`/`thos`/`visitors`/`webvpn`/`madmodel`/`library-*` 的 `page`/`status`，`campus.page`，以及 `local.agenda`、`local.agenda_changes`。
- 可用写入：`library.create_seat_reservation`、`library.create_room_reservation`、`library.cancel_reservation`、`sports.create_reservation`、`sports.cancel_reservation`；均需当次授权。

- 29 个 MCP 工具、6 个旧入口点 + `openthu-doctor`、`tsinghua-assistant` 协议标识与旧别名保持不变。

## 边界与限制

- 本模块以文档为主，但审计修复同时改动了 `facade/core.py` 与 `__main__.py`：`_local_failure` 的绑定和 `agenda --export --semester` 透传。它们没有改工具 schema、能力登记或发布元数据。
- 本机只执行 Linux；Windows 的文档可读性、命令兼容与全量测试由 CI 的 `windows-2025` job 覆盖，未在本机 Windows 主机复现。
- 真实校园认证、写入、付款、交作业、模型图片传输均未在本模块执行；文档只记录已有证据与阻塞。
- `local.resources` 在默认 CLI/MCP/看板中仍为 `RESOURCE_PROVIDER_UNAVAILABLE`；手册给出宿主 API 用法，不把它写成已接通的公共入口。
- 看板 HTML 外壳随 7.1 一起打包，CLI 的两条构造路径都传 `static_dir`，安装后 `/` 直接提供外壳；
  文档中的 `LOCAL_API_UI_NOT_INSTALLED` 现在只表示静态目录缺失或不可读。
- `actions.py` 顶部仍有旧 docstring “No campus write adapter is enabled in block 5”；该文件归 4.4，本模块未修改，已在 `docs/contracts/source-matrix.md` 的差异表中保留为 4.4 事项。
- `docs/contracts/source-matrix.md` 属 2.3 负责的来源证据文档；本模块未修改其内容，其中“4.4/7.3 统一措辞”一行仍是历史登记，由 2.3/8.1 在回接时更新。
- 候选构建只用于文档与包元数据核对，不是集成候选；`install-check` 由 8.1 在最终集成树执行。
