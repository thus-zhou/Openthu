## 关键安全属性

- 每次封装使用独立随机 12 字节 nonce；同一记录重复写入得到不同密文。
- AAD 绑定格式版本、用途、账号域、服务域、账号伪名和修订号；修改头、nonce、密文或域均失败关闭。
- 主密钥为随机 32 字节秘密，不由主机名/用户名派生；Linux 密钥文件必须在数据目录之外，Windows 密钥由当前用户 DPAPI 包装。
- 账号伪名由受保护的随机命名空间密钥经 HKDF 分离后 HMAC 生成；轮换数据密钥后保持稳定，跨账号/跨用途读取被拒绝。
- 旧 `LA-DPAPI-1`、`THU-ACTION-1`、`THU-TODOS-1` 仅在匹配的 Windows 用户下只读；跨平台读取返回需要重新建立会话。
- 轮换先逐条解封、重封、核验，再原子切换 `store.json`；失败保留旧指针、旧目录和旧密钥，不自动清理。
- 错误只包含稳定错误码，不含路径、账号、密钥或密文。

## 2.2 审计修复（`6e99d3d` + `a6b54bb`）

- 记录 ID 现在写入可选 `record_id` 头字段并绑定进 AAD；复制记录到另一个 record path 返回 `SECURE_RECORD_MISMATCH`。旧的无 `record_id` 记录只在 legacy store 中只读兼容。
- `rotate()` 在创建 target 目录前验证新 provider 的 `key_path`，拒绝把 key 放进 data 目录；构造器也拒绝无法验证 key 位置的 provider。
- 新增 `THU_SECURE_RETIRED_KEY_FILES`（JSON 列表），重启后 `rollback()` 可加载旧 key；回退前逐条认证旧记录和 namespace，损坏则拒绝切换。
- `health()` 真正执行 GCM 认证，捕获不可读/损坏记录并计数；`health()`/`preview_rotation()` 不再抛出带绝对路径的 `PermissionError`。
- `a6b54bb` 进一步让 `health()`、`rotate()` 和 `rollback()` 都检查文件名与 `record_id` 一致，避免通过健康检查或轮换把替换后的记录继续传播。
- 首次 pointer 创建失败留下的空 `records-*` 目录可在重启时回收；记录读取受 `MAX_ENVELOPE_BYTES` 限制。
- Windows 数据目录/密钥父目录增加 ACL 检查/加固，拒绝 reparse point，并保留父目录继承以便新记录创建。

## 批次 2 复验（2026-11-17）

批次 2 整合复验发现并修复了一处 Windows 真实主机缺陷：

- `_windows_acl_owner_only` 过去用 `O:([^GDS]+)` 解析 SDDL 所有者。标准 SDDL 的 owner 是 `O:S-1-5-21-...`，SID 以 `S` 开头，因此任何普通用户 SID 都匹配失败，真实 Windows 主机会被误判为 ACL 不安全并抛 `SECURE_KEY_PERMISSION`。现改为按 SDDL 段解析 owner，并把 `SY`/`BA`/`OW`/`LA` 别名与完整 SID 归一化后比较；ACE 受托人同时接受别名和完整 SID。
- 该缺陷此前未被 CI 捕获：新增 5 个平台无关的合成 SDDL 测试（具体 SID、别名/完整 SID、内置管理员 LA、额外受托人、缺 DACL），Linux 与 Windows 都会执行。
- 轮换失败时清理本次创建但从未发布的 `records-*` 目录；不触碰活动目录或旧密文。
- 记录读取改为一次 `O_NOFOLLOW` 打开 + `fstat` 有界读取，减少 check-then-read 窗口；新增符号链接/非普通文件拒绝测试。
