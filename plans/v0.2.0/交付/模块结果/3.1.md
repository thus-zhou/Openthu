## 交付范围

本模块把会话、浏览器状态、网络学堂会话、事务日志和待办缓存的加密读写统一到
`secure-storage-header-v1` 与显式提供者选择，同时保留 Windows DPAPI 旧格式读取和
既有函数签名。

### 新增

- `src/thu_assistant/crypto-bridge.js`：Node 到受控 Python 加密服务的唯一客户端。
  固定动作、固定解释器/模块、请求编号、2 MiB 请求上限、2 MiB + 64 KiB 响应上限、
  超时、取消、子进程失联后仅当前调用失败，不重放。
- `src/thu_assistant/crypto_service.py`：私有逐行 JSON 服务。只接受 `health`、
  `inspect`、`seal`、`unseal`；密钥位置、数据目录和后端只来自子进程环境；请求
  不能选择程序、文件路径、密钥或数据目录；错误不返回明文。
- `runtime/windows/session-store.py`：`runtime/windows/access.js` 与
  `learn_assistant.auth.SecureSessionStore` 之间的兼容桥，允许旧 Windows 辅助入口
  使用新提供者并在无密钥时保留旧 DPAPI 行为。

### 修改

- `src/thu_assistant/gateway.js`：默认状态目录改用统一路径解析；会话存储接受
  `crypto` 或兼容 `dpapi` 注入；新增 `unseal_browser_state`；`browser_state` 返回
  封套而不返回明文；`import_browser_state` 接受 Python 传来的状态对象；学习会话
  签名同时识别 `session.secure` 与 `session.dpapi`。
- `src/thu_assistant/session-store.js`：支持 `campus-v3.secure`（`session` 用途、
  `CAMPUS` 账号域、`LOCAL` 服务域、`campus-session` 记录号）；保留
  `campus-v2.dpapi` 读取/写入兼容；旧文件在首次新格式写入前复制为
  `.before-v3`；新封套写入后立即解封比对；账号、修订号、记录号和作用域全部核验。
- `src/thu_assistant/browser.py`：不再直接调用 Python DPAPI 函数；通过网关解封
  引导状态和 SSO 刷新状态，通过网关封装回存；持久化失败保留明确状态；账号切换
  或身份查询失败时关闭会话并拒绝继续使用旧账号页面。
- `src/learn_assistant/auth.py`：`SecureSessionStore` 新增 `session.secure` 写入、
  账号绑定、旧 `LA-DPAPI-1` 只读兼容、保存前备份、临时文件解封核验后原子替换；
  `_dpapi_protect` / `_dpapi_unprotect` 保持原签名，先尝试新提供者，再回退 Windows
  DPAPI；`_dpapi_unprotect` 只接受 `ACTION`/`LOCAL` 封套，配置密钥不可用时失败关闭。
- `src/thu_assistant/gateway_client.py`：新增 `gateway_environment()`，使用 2.1 的
  路径默认值和显式环境槽解析状态目录、密钥文件、学习会话目录、Python/Node；
  相对密钥路径在启动前拒绝。
- `runtime/windows/access.js`、`runtime/windows/import-session.py`：改为优先使用
  新会话存储，只有未配置新密钥时才保留旧 DPAPI 兼容；helper 不可用、密钥已配置
  或账号未绑定时失败关闭，不静默读取旧 DPAPI。
- 新增测试：`tests/test_session_gateway.py`、`tests/campus-session-v3.test.js`、
  `tests/campus-crypto-bridge.test.js`；更新 `tests/test_campus.py` 与
  `tests/fixtures/session-writer.js` 以覆盖新协议。

- `browser.py` 原先在方法内直接导入 `_dpapi_unprotect` / `_dpapi_protect`；
  已移除，改走网关受控命令。

## 渐进迁移规则

1. 先读 `campus-v3.secure`；不存在时读 `campus-v2.dpapi`。
2. 旧状态通过匹配的 DPAPI 兼容读取；读取失败不视为退出登录：
   - Windows 且 DPAPI 可用：返回 `STATE_DECRYPT_FAILED`，保留旧文件。
   - 非 Windows 或 DPAPI 不可用：返回 `SECURE_LEGACY_UNAVAILABLE`，提示需要重新
     建立会话。
3. 首次写入新格式前，把 `campus-v2.dpapi`、`campus.dpapi`、`browser.dpapi` 复制为
   `.before-v3`（`COPYFILE_EXCL`，只保留第一次迁移检查点）。
4. 新封套先写入临时文件、`fsync`、原子替换；随后立即解封并逐字节比对明文。
5. 只有核验通过才返回 `saved=true`、`verified=true`；旧密文不删除。
6. 浏览器回存失败返回 `sessionPersisted=false` 与具体 `sessionPersistenceError`，
   不声称已保存。

迁移结果字段（保存在加密状态内，不进入公开结果）：

```json
{
  "source": "LEGACY_DPAPI",
  "target": "SECURE_V3",
  "legacyPresent": true,
  "legacyReadable": true,
  "saved": true,
  "verified": true,
  "legacyRetained": true
}
```

## 受控通信协议

- Node 启动固定 argv：`python -m thu_assistant.crypto_service`（测试可注入显式
  `argv`，生产配置不提供该入口）。
- 请求：`{id, action, ...非秘密作用域}`；`id` 为 128 字节以内的不透明字符串。
- 允许动作：`health`、`inspect`、`seal`、`unseal`。
- 请求不得包含 `program`、`argv`、`python`、`path`、`key_file`、`key_path`、
  `data_dir`、`env` 等字段。
- 请求上限 2 MiB；响应上限 2 MiB + 64 KiB；超时默认 15 秒；取消或超时立即杀掉
  当前子进程，下一次调用重新建立，绝不重放前一请求。
- 子进程环境只含操作系统运行所需变量和
  `THU_SECURE_KEY_FILE` / `THU_SECURE_DATA_DIR` / `THU_SECURE_BACKEND`；不继承
  账号、密码、Cookie 或 MCP 请求内容。
- 解封明文只回到网关内存或浏览器内存；MCP 结果和日志不含明文。

## 安全结果摘要

- 会话封套使用 `secure-storage-header-v1`；用途 `SESSION`，账号域 `CAMPUS`，
  服务域 `LOCAL`，记录号 `campus-session` / `browser-session`。
- `campus-v3.secure` 为二进制封套，权限 0600；旧 `campus-v2.dpapi` 只读保留，
  首次迁移复制为 `.before-v3`。
- 校园状态同时校验状态内哈希、封套 `account_ref` 和运行中的当前账号；学习会话
  也以 `THU_LEARN_ACCOUNT` 绑定账号，账号切换时 `load`、`commit` 和浏览器快照拒绝。
- Windows access helper 在密钥已配置但 Python 会话桥不可用时 fail-closed，不回退旧 DPAPI。
- 修订号绑定进 AAD；封套读取后与状态 `revision` 比较，防止把旧状态当新状态。
- 浏览器状态只通过网关私管道解封；MCP 返回值只有密文 `sealedState`。
- 配置密钥但不可用时失败关闭，不回退 DPAPI 或明文。

## 剩余边界与移交

- 上游 `vendor/madmodel-proxy` 的 CookieJar 只保存 name/value/path；
  `runtime/windows/access.js` 会过滤已过期 cookie，但无法在不修改 vendor 的前提下
  完整往返 expires/secure/httpOnly/sameSite，保留为兼容边界。
- 自定义 `OPENTHU_CONFIG_FILE` 的 `storage.state_dir` 尚未由 `gateway_environment`
  读取；正常 GatewayClient 环境路径已覆盖，完整配置解析留给 2.1/6.3。
- 云主机为 Linux；Windows DPAPI/ACL 由 GitHub `windows-2025` 的
  `test_windows_dpapi_legacy_session_is_read_by_real_helper` 证明，本地不声称已运行。
- 不承诺抵抗能同时替换数据与指针的完整目录回滚；修订号和记录号只解决普通并发
  与单记录替换。
- `action_store` / `todos` 的外层 `THU-ACTION-1` / `THU-TODOS-1` 魔数未改；新封套
  嵌套在旧容器中，真正的记录标识和业务迁移留给 4.4 / 5.4。
- `learn_assistant/providers/web.py` 的提示已改为读取 `SecureSessionStore.protection`；
  跨模块 `LoginStatus.error_code` 和 `mcp_stdio` 账号环境接线已登记给 6.1/7.3 owner。
- `catalog.state_root`、`learn_assistant/core.py` 的旧状态路径属于 2.1 已登记的
  4.2 / 6.3 迁移项，本模块不改。
- 上游 `vendor/madmodel-proxy` 未修改；账号/模型令牌提供者包装留给 4.4 / 6.1。
- 对 2.2 的 `secure_store/keys.py` 做了一处集成修复：其私有 DPAPI 路径改用
  `_dpapi_protect_legacy` / `_dpapi_unprotect_legacy`，避免创建或解包主密钥时
  重新进入新提供者。原语行为不变，仍需 2.2 owner 复核。
