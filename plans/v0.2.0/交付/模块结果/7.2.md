## 边界与保留限制

- 7.1 是同一批次尚未回接的模块：矩阵把 `tests/test_web_assets.py` 标为 `pending_same_batch`，
  本工作区没有该文件；7.2 验证的是 6.2 的本地读取 API 协议和进程边界，不是 7.1 的看板界面。
  7.1 回接后必须把矩阵状态改为 `covered` 并补上真实看板用例。
- 7.3 是文档模块，8.1/9.1 是后续串行关口；矩阵分别标为 `documentation_only` 和 `future_gate`，
  没有为它们伪造测试。
- 本机为 Linux：Windows DPAPI、Windows ACL、Windows 会话迁移等用例以明确平台原因跳过。
  真实 Windows 结果必须由 CI 的 `windows-2025` 作业在同一提交产生；本记录的发布门禁因此
  保留 `platform_report_missing`，不把跳过、形状报告或本机聚合当成 Windows 证据。
- 跳过原因使用登记表；新增原因必须登记或使用 `platform:`/`env:` 前缀。跳过比例超过 5%
  记为 `INCOMPLETE`，未登记原因记为 `FAIL`；这是有意的策略，不是遗漏。
- 精确标记扫描覆盖全部候选归档，只按归档内路径跳过 `tests/security_regression/marker_set.json`
  这一个已提交的标记定义文件。源码包/sdist 仍由 `privacy_scan.py` 的通用规则和 POSIX 路径规则
  覆盖；源码包中的测试和合成标记定义不会被误报为泄露。
- 故障注入使用 5.3 的合成提交传输和 2.2 的临时密钥；没有生产上传端点、真实账号或真实业务写入。
- 本地读取 API 超时用例用事件同步等待门面进入；工作线程仍可能在请求超时后继续，直到服务停止，
  这是 6.2 已记录的进程边界，不是本模块新增的取消能力。
- 报告只保留错误类别和仓库相对节点编号；原始失败材料留在受控环境。跳过原因也经过路径/令牌
  脱敏，但报告仍是工程摘要，不是通用的数据防泄漏系统。
