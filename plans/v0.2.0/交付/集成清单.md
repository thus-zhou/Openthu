## 五、候选构建与恢复安装

构建、校验、仓库外安装、缺密钥与缺资源行为统一记录在 `候选版本记录.md`；本节只登记入口：

```text
python scripts/package_release.py build
python scripts/package_release.py verify --expected-commit <候选提交>
python scripts/package_release.py install-check --dist dist
```

候选资产写入 `dist/`（已被 `.gitignore` 排除），不把二进制提交进仓库；同一提交的产物、`release-manifest.json` 与 `SHA256SUMS` 必须互相一致。

最终候选由 CI `release gate` 在 `ac94b63` 上重建：4 个产物、源码 565 文件、wheel 214 成员（54 随包）、sdist 496 成员，九项门禁检查全 true、0 gap（push `44197852215`、PR `44197861613`）。8.1 的审计修复把“可复核的提交链”补齐：交付提交 `c81a877` 含测试、CI 修复与报告归因，集成提交 `5ec73d9` 把模块分支合入 `hermes/1-install-diagnostics`，版本 PR #2 的 head 不再是批次 7 的旧树。

## 六、保留边界与外部阻塞

- 来源阻塞（非缺陷）：续借请求契约、作业提交端点、学业四项来源、模型图片协议均为 `BLOCKED_SOURCE_EVIDENCE`；候选不把它们写成可用。
- 本地看板只读；Firefox/Safari 的静态子资源 `Sec-Fetch-Mode` 未验证，能力声明只到 Chromium 实测。
- `local-read-api-v1` 的 HEAD 仍执行一次读取但不占 10 秒刷新配额；bootstrap 令牌一次性，本地会话过期需重启实例。
- 旧 `learn_assistant.core.prepare_submission` 仍写入本地未加密预览 JSON（含本地路径，不上传、不提交），属 v0.1 兼容路径的本机状态边界。
- 真实预约、取消、付款与提交仍需使用者对具体事项的明确指令；工程验证不提升真实业务证据等级。
